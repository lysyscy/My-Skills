# 形态 B：多表复原（多张乱表 → 各自规范）

## 适用与目标

一份业务清单被手工拆成多张工作表，拆分时**表头行被删掉、每张表起始列不同**，序号跨表重号。
目标是**每张表各自成为规范台账，不合并成一张大表**。

典型场景：工程设备材料清单、采购清单、台账拆分表。

## 方向性铁律（本形态专属）

**不合并工作表** —— 用户明确要求逐表整理时，合并是方向性错误，不是细节。

其余共用铁律（源文件不覆盖 / 不猜不补 / 按表头名定位列 / 独立校验 / 交付范围不等于用户要求）见 `SKILL.md`。

## 第 1 步：先摸清真实结构，不要相信自动表头识别

`inspect_workbook` 之类的通用检查器会**把第一行当表头**，对这类文件必然误判。用脚本直接输出每列的非空数、首个非空行、首个非空值：

```python
for c in range(1, ws.max_column + 1):
    vals = [(r, ws.cell(r, c).value) for r in range(1, ws.max_row + 1)
            if ws.cell(r, c).value not in (None, '', ' ')]
    if vals:
        print(gl(c), f"非空{len(vals)}", f"首行R{vals[0][0]}", repr(vals[0][1])[:40])
```

同时输出 `ws.merged_cells.ranges` —— 合并单元格是判断「一台设备占多行」的关键线索。

## 第 2 步：识别四类结构问题

| 问题 | 识别方法 | 处理 |
|---|---|---|
| **无表头** | 首行是数据不是字段名 | 新增统一表头行 |
| **起始列不同** | 各表第一个非空列不同（B/C/D） | 逐表显式配置列映射，不要用统一偏移 |
| **整行错位** | 某行起列位置偏移一格，数量列出现单位文字 | 逐行分段配置，**用行号判定断点** |
| **两段拼接** | 同一表内序号断裂回 1、列位置中途改变 | 按行号分两段，各配一套列映射 |

⚠️ **列位断点必须用行号实测**：例如某表 R2–R10 是 C/D/E/F/G，R11 起是 D/E/F/G/H，断点是 `r <= 10`。
凭"看起来"猜会错，且错了会静默把单位当数量。

## 第 3 步：把混在一起的规格列拆成三列

原始规格列常把三类信息挤在一格。按**材质牌号正则**抽取最可靠：

```python
MAT_RES = [
    r'20-GB/T\d+',
    r'\d{2}\s*GB/T\s*\d{3,5}(?:\.\d+)?[A-Z]?',   # 必须带 (?:\.\d+)?[A-Z]?
    r'NB/T\s*\d+(?:\.\d+)?[A-Z]?',
    r'GB/T\s*\d{3,5}(?:\.\d+)?[A-Z]?(?![0-9A-Za-z])',
    r'HG/T\s*\d+(?:\.\d+)?[A-Z]?(?![0-9A-Za-z])',
    r'Q\d{3}[A-Z]?(?:/GALV)?',
    r'\b316SS\b|\b304SS\b|\b316L\b|\b304S\b',
    r'A\d{3}(?:\(C?<=\d\.\d\))?',
    r'\bWCB\b', r'(?<![A-Za-z])CS(?![A-Za-z])', r'\bSMLS\b',
]
```

⚠️ **标准号正则必须匹配到词尾**。只写 `GB/T\s*\d{3,5}` 会把
`HG/T 20623B` 截成 `HG/T 20623`（丢后缀字母）、`GB/T713.2` 截成 `GB/T713`（丢小数）。
必须加 `(?:\.\d+)?[A-Z]?(?![0-9A-Za-z])`。**这是本类任务最容易造成静默数据丢失的坑。**

归类规则：

- **材质/牌号** → 钢号、不锈钢牌号、标准号（`Q235` `316SS` `20 GB/T9948` `Q245R`）
- **规格型号** → 压力等级、公称通径、壁厚等级、几何规格（`PN25` `DN25` `SCH80` `∠50x50x5`）
- **技术参数** → 接口结构、防爆等级、性能描述、英文原文（`对焊BW` `ExdIICT4` `流量：xx`）

抽取后必须清理被挖空残留的孤立标点：

```python
rest = re.sub(r'(^|[ ，,、;；:：])[,，、;；:：]', r'\1', rest)
rest = re.sub(r'[,，、;；:：]\s*$', '', rest)
```

**名称列绝不参与抽取** —— 名称里常含标准号（如 `盲法兰 HG/T20615-2009`），
抽一次就变成 `盲法兰 HG/T20615`，是数据损坏。

## 第 4 步：一台设备占多行时合并

储罐/风机/泵/成套设备常一台占 3–6 行，参数挤在规格列。合并规则：
首行取名称/规格/单位/数量，其余行的规格文本按顺序合并进「技术参数」，单元格内用 `\n` 分隔。

尺寸型规格（`Φ`、`DN`、`VN` 模式）应抽到「规格型号」列而非留在参数里。

**是否拆成独立参数列（设计温度/压力/流量/功率各一列）要问用户** ——
用户常选择「保持一列文本」，因为四张设备表表头不一致反而更难用。

## 第 5 步：打待补标记（分类型）

```
缺数量 / 缺规格 / 规格无型号 / 占位符未填 / 缺单位
```

- `缺规格`：规格空且无材质无参数
- `规格无型号`：规格空但有材质或参数（内容是描述性文字，无可比型号）
- `占位符未填`：写了但没填值（正则 `\bhold\b|\bTBD\b|待定|未定`）

**给本就不适用某字段的行加豁免**，否则会大量误标。例如控制点行（IO 点、操作站）
本就没有规格，应传 `no_spec_ok=True`，否则 16 行全被误标「缺规格」。

## 第 6 步：独立校验（最容易出错的一步）

⚠️ **校验脚本必须按表头名定位列，不能写死列号**。写死列号在新表增加了
「设备位号」列后会整体错位，产出一堆**假阳性**。

```python
h = {ws.cell(1, i).value: i for i in range(1, ws.max_column + 1)}
iS, iM, iP, iN = h['规格型号'], h['材质/牌号'], h['技术参数'], h['名称']
```

⚠️ **校验必须直接读源文件原文，不能复用中间产物**。若把拆列结果先写进一个
截断到 60 字的审计 JSON 再拿去做完整性检查，会得到几十条假「丢失」。

**三层校验，缺一不可**：

1. **行数 + 名称/单位/数量逐格比对** —— 用源表列映射重新取真值，与新表按表头名定位的列逐格比。
   比较文本前先 `re.sub(r'\s+', '', ...)` 归一，否则压缩空格会造成假差异。
2. **拆列完整性** —— 源规格列全文里的每个 token（中文 ≥3 字、字母数字 ≥4 字符）
   是否都出现在新表三列拼起来的内容里。这是发现静默丢失的唯一手段。
3. **数量合计** —— 本类任务不改数量，逐格相同即可；但若做了合并要另行核对。

**假阳性比假阴性更浪费时间** —— 出现成片差异时，先怀疑校验脚本本身
（列号错、行偏移、取的是位号列而非名称列），再怀疑生成逻辑。

## 第 7 步：同材料行合并（可选，常跟在整理之后）

采购场景的常见诉求：**同一材料不能让供应商填两遍价格**。

**判定规则**：名称 + 规格型号 + 材质/牌号 **三者全同**（`norm()` 去空格后比较），
**且技术参数与备注无差异**，才合并。三者缺一不可 —— 只比名称会把不同口径、
不同材质的料合到一起，导致买错或报不准价。

**落地前必须先扫描候选并按性质分类**，这一步是事实核查而非决策：

| 类 | 特征 | 处理 |
|---|---|---|
| A 真同材料 | 名称+规格+材质全同，参数同 | 合并，数量相加 |
| B 仅材质不同 | 规格同、材质异 | **绝不合并**（买错材质） |
| C 仅规格不同 | 名称材质同、规格异 | 慎合，合并后不便报价 |
| D 三列皆空 | 规格材质参数全空 | 需人判断，可能分部位各计一次 |

⚠️ **多数表里 A 类极少甚至为零**。真实工程清单里同名不同规格是常态，
先跑扫描拿到真实数字再给用户看，不要预设"有很多重复可合"。

**合并前的预检**（缺一不可）：

```python
# 名称/规格/材质/单位必须全同
# 数量必须全是数字（否则无法相加，如 "2+1"）
# 参数/备注差异要打印出来人工判断
```

⚠️ **数量合并的最大 bug —— 嵌套列表**：

```python
# 错：结果是 [[3, 61]]，min() 返回列表，r == min(g) 恒为 False
group_rows = [g for g in [rr for shx, rr in GROUPS if shx == sh] if r in g]
# 对：返回扁平的 [3, 61]
all_rows = [rr for shx, rr in GROUPS if shx == sh]
group_rows = next((g for g in all_rows if r in g), None)
is_merge_keep = bool(group_rows) and r == min(group_rows)
```

若这个判断失效，**被并的行会被删掉但保留行数量没换成合计** —— 数据静默丢失且总量对不上。

**合并的校验判据**：

1. **每张表数量总和必须与合并前完全一致** ← 最关键的一条
2. 每组合并后只剩 1 行且数量为合计
3. 未合并组原样保留（检查备注、口径等区分字段是否还在）
4. 行号连续性

⚠️ 校验时**必须用「名称+规格+材质」三键定位**。只按「名称+规格」两键会误判
「同名称同规格但材质不同」的独立行，产生假「残留」与假「被误合」。

## 第 8 步：交付

- 整理版另存 `<原文件名>_整理版.xlsx`，源文件不动
- 合并版再另存 `<原文件名>_合并版.xlsx`，整理版也不动
- 合并行用**淡绿底色**标记，便于人工复核
- 写一份说明 md：原表问题逐表列出、整理后行数、统一表头、字段归类规则、
  **明确没做的事**、待补数据统计、数据核对结果、合并规则与合并明细
- 交付前 `ls -la` 确认源文件与整理版时间戳均未变

## 追问清单（拷问时先问这些）

1. 最终用途是什么（询价下单 / 报量 / 存档 / 导入系统）？决定标记严格程度
2. 缺数据的行怎么处理（保留标记 / 拆出去 / 只写文档）？
3. 标记分几类？要不要分优先级？
4. 总表与分表口径是否相同（决定是否对账）？
5. 行编号用原序号还是每表重编？
6. 要不要追溯列（来源 / 原行号）？
7. 拆列要不要推广到全部表？
8. 压力等级、防爆等级分别归哪列？
9. 合并单元格向下填充还是保持？
10. 工作表名改不改、输出到哪、叫什么？

**合并阶段追加追问**：

11. 合并目的是什么（简化询价单行数 / 删重复录入 / 看合计 / 打包询价）？**先问这个再问规则**
12. 「同一材料」怎么判定（名称 / 名称+规格 / 名称+规格+材质）？
13. 参数或备注不同的行要不要合？
14. 合并后数量怎么写（相加 / 相加+分项明细 / 不记来源）？
15. 被并的行要不要能回溯（保留原行+标色 / 真合并另存）？

⚠️ **拷问第 11 条时先给事实再问**：把扫描出的候选按 A/B/C/D 四类分类、
把"真正完全重复录入有几行"摆出来。用户常以为有很多重复，实际常常是 0 行 ——
这时问题的性质会从"怎么合并"变成"那到底要解决什么"。
