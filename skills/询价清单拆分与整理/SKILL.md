# 询价清单拆分与整理

把工程材料 / 询价清单整理成可交付台账。输入形态有两种，**先判定形态再动手**；两条流水线的方法学与铁律共用。

## 第 0 步：判定形态（必做，不要跳过）

先跑第 1 步的结构摸底，再按下表归类：

| 摸底结果 | 形态 | 加载 |
|---|---|---|
| 一张（或少数几张）工作表，**有**标题行与表头行，列位齐整，但多个类别混在一起 | **A 单表拆分** | `references/A-单表拆分.md` |
| 多张工作表，**多数没有表头行**，各表起始列从 B/C/D 各不相同，序号跨表重号 | **B 多表复原** | `references/B-多表复原.md` |
| 两种特征都有（既有大表又有零散小表） | 先 B 后 A：先逐表理顺，再按类别重组 | 两份都加载 |

⚠️ **判错形态是方向性错误，代价最大**。拿不准时真跑摸底脚本看数字，不要凭"看起来"。

## 共用铁律（两种形态都适用）

1. **源文件永不覆盖** —— 一律另存新文件；交付前确认源文件时间戳未变。
2. **不猜、不补数据** —— 缺失就留空并打标记，绝不用"看起来合理"的值填充。
3. **按表头名定位列，不写死列号** —— 写死列号在新增一列后会整体错位，产出成片假阳性。
4. **独立校验** —— 校验脚本直接回读源文件原文，不复用生成脚本的中间产物；**校验口径必须与生成口径逐字一致**（口径不一致会互相误报，两边都白干）。
5. **不擅自归一化** —— 用户说"完全相同才合并"就逐字比；把归一化后能合的组**列出来给用户决策**，比替用户决定更稳。
6. **数量总和守恒** —— 任何合并/拆分/排序动作后，数量合计必须与操作前逐格相等。
7. **交付范围严格等于用户要求** —— 用户说加两列就只加这两列；擅自补"看起来有用"的列会被直接驳回。
8. **合并单元格：先写值、最后统一设 border** —— openpyxl 的 `cell.font` 永不为 `None`，遍历合并单元格读样式会抛异常并覆盖刚写的公式（踩过：合计行 SUM 静默消失）。
9. **删除输出文件用完整文件名** —— `rm -f "路径*.md"` 会连带删掉同前缀的说明文档。
10. **静态产物不可变** —— 已交付的版本先存指纹（md5）或整目录备份，再改脚本；改完重跑比对，确认零影响。

## 第 1 步：结构摸底（两形态通用，先跑这个）

不要相信通用 table 检查器 —— 它会把第一行当表头，对本类文件必然误判。逐列输出非空数、首个非空行、首个非空值：

```python
for c in range(1, ws.max_column + 1):
    vals = [(r, ws.cell(r, c).value) for r in range(1, ws.max_row + 1)
            if ws.cell(r, c).value not in (None, '', ' ')]
    if vals:
        print(gl(c), f"非空{len(vals)}", f"首行R{vals[0][0]}", repr(vals[0][1])[:40])
```

同时打印 `ws.merged_cells.ranges`（判断"一台设备占多行"的关键线索）、`ws.max_row`、`ws.max_column`、每张表的行数。`.xls` 用 `xlrd`，`.xlsx` 用 `openpyxl`。

## 形态 A 骨架（单表拆分）

1. **建分类映射**：提取去重后的**名称全集**，逐个显式写进 `NAME_CAT`，并断言每一行都命中 —— 不遗漏、不重复、不猜。
2. **拆列**：把混在一起的「规格型号」拆出「技术参数」（触发条件：含换行 / 含全角冒号 / 去换行后长度 ≥ 30）。必须加**恒等式断言**：`规格型号 + 技术参数 ≡ 源规格型号`，防静默丢字。
3. **去重**：口径分严格 / 宽松两档；**分组键必须覆盖所有"承载差异"的列**。
4. **排序**：品类逻辑序 → 规格口径升序 → 材质 → 技术参数 → 备注。口径必须**按数值**比，且剥掉角度前缀与壁厚系列。
5. **套模板**：跨工作簿不能搬 `_style`（那是源簿样式表索引），必须搬真实样式对象。
6. **输出**：每类别一张工作表；或合并为一个文件多工作表。

## 形态 B 骨架（多表复原）

1. **逐表实测列位断点**，用行号判定，不靠"看起来"。
2. **拆列**：按材质牌号正则把混在一起的规格列拆成三列；**名称列绝不参与抽取**。
3. **设备多行合并**：一台设备占 3–6 行时，首行取名称/规格/单位/数量，其余行文本按序并入技术参数。
4. **打待补标记**：缺数量 / 缺规格 / 规格无型号 / 占位符未填；对本就不适用某字段的行加豁免。
5. **三层独立校验**：行数与逐格比对、拆列完整性 token 检查、数量合计。
6. **交付**：另存 `_整理版.xlsx`，需要时再出 `_合并版.xlsx`。

## 参考实现（`scripts/`）

| 脚本 | 用途 |
|---|---|
| `inspect_structure.py` | 结构摸底 + 形态判定（两形态通用，直接跑；先跑这个） |
| `split_by_category_example.py` | 形态 A：分类拆分 + 去重 + 排序 + 套模板；改文件头配置区即可复用 |

`assets/询价单模板_空白.xlsx` —— 空白询价单模板（标题占位符 + 11 列表头 + 样例行 + 合计行 + 完整样式），无业务数据，可直接当模板套用；完整规范见 `references/询价单模板规范.md`。

## 拷问清单（动手前问清楚，避免返工）

1. 最终用途（询价下单 / 报量 / 存档 / 导入系统）？决定标记严格程度。
2. 输出形态：每类别一个文件，还是一个文件多张工作表？
3. 目标类别清单，以及本表没有的类别怎么处理（跳过 / 生成空表）？
4. 列结构：保留原列，还是套用户现有模板（模板路径在哪）？
5. 「同一材料」怎么判定？数量怎么合（相加 / 相加+明细 / 不记来源）？
6. 序号：每张表重编 1..N，还是沿用原序号？
7. 排序：同名称聚块后按什么排（口径 / 名称 / 项数）？
8. 待补项怎么标、标几类？
9. 要不要追溯列（源行号 / 来源表）？
10. 标题行文案（项目名 / 付款条款 / 地址）—— 占位符必须清零。

⚠️ **先给事实再问**：把摸底得到的真实数字（各类行数、疑似重复组数、缺数据行数）摆出来再提问。
用户常以为"有很多重复可以合"，实测常常是 0 组 —— 这时问题性质会从"怎么合并"变成"到底要解决什么"。
