# 实施已授权工作

1. 读取项目入口，确认本次目标、验收、权限和已有修改；只补本次需要的源码与背景。用户给出票引用时先核其真实标题和范围。
2. 普通任务按项目约定实施，自主判断是否使用子代理；委派不以建票或采用跨票统筹为前提。有实际跨票依赖、隔离与累计整合需要且已采用统筹时，读 [跨票统筹](references/coordination.md)。
3. 决定委派后，按宿主已采用的子代理配置规则选择模型、思考强度和上下文并核对实参，明确目标、交付和写入边界。无法确定或通过工具表达合适配置时，仅暂停该次派遣，继续可独立完成的工作；返回结果未展示运行配置时如实标为未验证。
4. 按项目实际入口选择足以验证改动的最小检查集合，项目必跑检查仍执行，复用仍有效的证据。相关检查通过且下一步审查的实质发现关闭后即停止验证；仅新改动、新失败或明确覆盖缺口才能扩测或重复，并说明要回答的新增问题。不为更放心、更完整或增加通过数而加码。处理本次造成的失败，报告无关失败与未验证部分，不改预期换绿灯。
5. 同步受影响的项目正文，按后果和覆盖缺口选择自查或独立审查，关闭本次实质发现。用户明确要求或已采用流程中的独立审查必须完成。
6. 按项目规则退出本任务资源并完成已授权保存；保护原件、在用资源、他人修改与独有状态。报告实际结果、验证范围及提交/发布状态，不把部分完成报为全部完成。

业务口径、数据隔离、环境命令、预览与发布规则由项目持有。完整调用上游技能时遵守其实际流程；不用技能摘要替代必要指令。
