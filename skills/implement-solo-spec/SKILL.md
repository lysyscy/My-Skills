# 个人实施入口

跨项目使用，输入可以是已确认需求、规格或关联票；票来源和收尾方式按项目约定。所有个人实施从本入口判断普通模式或整体统筹模式，验证深度另按实际风险决定。调用入口或引用章节不等于启用整体统筹；既有任务沿用其已授权模式和范围。在当前授权范围内完成实施，平衡用户介入、等待、token、验证和返工成本。

本技能是个人实施节奏和收尾的唯一规则主人，Matt 原版提供按需参考的方法。整体统筹模式使用下文的动态分派、累计验收和评审安排。项目范围、业务验收、授权和记录协议继续生效；用户的串行、隔离等限制按原适用范围保留。

先读项目 Agent 入口，按当前动作取适配章节，定位规格、相关票、真实执行入口与验证反馈；足以确定范围、预期和验收时结束初查。后续只补缺失、冲突或已变化的资料，复用本轮已读内容；查询先定位标题或符号，再读命中段。独立查询可合并，但每项只输出定位结果、必要片段或统计；完整日志留文件，失败时取对应段。按输出预算限制读取量，截断后只补缺口。预期来自已确认规格及业务权威，有编号时回读对应定义；程序输出用于核对与排错，技能不缓存项目路径、命令或业务规则。

## 普通改动

开工分别判断需求是否已清楚、是否需要规格或票记录、实施是否需要统筹。输入足以确定预期、范围和验收时直接实施或按项目协议拆票；需求与取舍尚未确定时才进入澄清或规格阶段。拆了多票仍按实际依赖和集成判断调度。

普通模式是默认：当前一批能够独立完成和验收时，按本节实施、验证及收尾。跨批接续、复杂依赖协调、共同集成或累计验收需要整体安排时，选择整体统筹模式。临时调查或专项审查使用子代理不自动改变模式。模式取决于工作关系与交付边界，验证深度取决于风险；行数、文件数、票数及“极小”标签不单独决定任一项。

普通模式沿当前实施授权直接执行，无需让用户选择技能名。整体统筹模式先核采用授权：用户明确采用，或项目已授权 Agent 自主选择时，说明依据并记录模式、范围与授权来源；项目要求明确采用而尚无记录时，仅确认这项必要决策。原已采用整体 effort 的记录继续有效，不因入口归一降回普通模式；当次串行、隔离和范围限制继续生效。

### 外部方法消费边界

按需参考实际安装的 Matt `implement` 与 TDD 的实施、测试方法，复用本轮已读且有效的内容；参考不等于完整调用。两个个人模式均由本文及项目规则负责验证、发现关闭、资料同步和保存，集中收尾一次。用户明确要求完整采用外部技能时，核其强制步骤与当前授权，明确最终审查和保存由哪套流程完成；与已采用个人模式或当次限制冲突时交用户裁定。保持 Matt 原版不变，不将两套全量测试、审查和提交步骤叠加，也不能跳过原版步骤却声称完整采用。

仅消费 TDD 方法时保留公共边界、red-before-green、逐个行为切片及有效缺陷保护。已有公开接口与已确认验收足以选技术测试接缝时，由 Agent 记录选择及覆盖边界并直接验证；接口承载的业务含义未决、实质范围变化或缺失授权才需用户决定。完整调用 TDD 时沿用其确认要求。纯文档调整不强制 TDD。

### 当次能力发现

遇到陌生领域、明显能力缺口、重复失败或准备编写大量工具性代码时，按[按需能力选择](../improve-workflow/references/improvement-selection.md#按需能力选择)检查、比较、小场景验证并在当次授权内使用；可靠既有能力足够时直接复用。此处负责当次实施，不启动全面复盘或修改个人方法。长期能力采纳及包生命周期由 improve-workflow 负责。

项目入口可要求普通任务读取本节与“验证与失败处理”，无需启用整个 effort 循环。按当前请求完成必要调查、实现、相关验证、聚焦核验、资料同步和收尾；不强制先生成规格或拆票。已有输入足以确定预期、范围和验收时结束澄清；遇到业务口径冲突、实质范围变化或必要授权缺口时，先整理证据与推荐选择再交用户裁定。

验证按下文覆盖实际受影响路径；业务高风险、共享契约、跨模块影响或证据薄弱时扩大验证及必要的独立审查，项目已有的风险审查要求继续生效。小任务直接自做，确需分派时再读“动态分派与隔离”和“模型与推理强度”。普通改动不触发 effort 最终双轴的固定节奏；实际进行了审查时，按“发现关闭与额外审查”处理发现。

资料同步与现场收尾读 [文档维护约定](../setup-solo-workflow/references/document-maintenance.md)，按项目绑定操作。文档架构整改及规则迁移另读其“目录与规则职责”：沿本次授权收敛现行正文，同批接好入口、扫描范围及实际机器消费者；历史和兼容指针不提供额外执行授权，不把资料搬迁扩大为产品、测试体系或服务改造。验收、证据与状态相符，必要检查和收尾完成后结束；只有新变化、失败或未决风险才扩大或重复调查、验证。提交、部署及结构操作按项目授权。

## 整体统筹模式

已获采用授权后，使用下文的输入接续、执行循环和累计评审安排。普通模式按具体需要引用输入准备、分派、模型或发现关闭规则；这不启用整套统筹流程。

## 输入与分批接续

拆票时可仅引用本节准备实施输入；输入兼容本技能不等于采用其调度。沿用 Matt 的规格与票模板及项目票协议：

- 共同规格记录范围、业务权威指针、已确认取舍、票索引与真实依赖、共享接合边界、验证入口、整体完成条件和授权。
- 每票具备完整且可独立验收的用户路径、阻塞关系、状态、规格指针、相关业务引用、独有验收及验证类型。发布前核范围闭合、验收可判、依赖无环、指针有效；影响方向、范围或验收的未决先裁定。
- 采用记录、已交付接合与必要未决事项存入共同规格或所属票，按项目协议更新。具体实现细节留给实施者，已有事实通过指针复用。

用户指令，或 effort 中包含授权来源与范围的有效采用记录，已明确采用整体统筹模式时，后续新对话沿用该记录。用户指定单票或批次时，只完成当次授权范围及必要接合；开工核前置实际状态，未满足的依赖列为阻塞，不自动纳入实现范围。整项授权可连续推进，无需批次间重新请求授权。

已采用整体统筹模式的 effort，每批记录范围与基点，并沿用整个 effort 的固定评审起点和累计差异边界；起点存在未提交改动时保留可回溯边界。保存快照时按纳入范围核文件清单与内容完整性，清单无损处理路径（Git 可用 NUL 分隔）；缺项先核来源、保留修补依据，再接受审查材料。批次完成后做相应聚焦核验并按项目协议收尾；全部集成后再做一次覆盖整个 effort 的双轴审查，最后一批的局部差异不能代替累计范围。接续记录按文档维护约定复用票和证据指针。

## 主 Agent 的执行循环

仅用于已采用整体统筹模式的任务。

1. 读规格、票与依赖，核工作区及其他任务修改，按“输入与分批接续”钉评审起点、累计差异及当次授权边界。有 Git 时用一条集成分支承接结果，复用适用分支或在已授权实现范围内创建必要本地分支；无 Git 时确定可回溯的改动基线。按项目记录协议注明整体统筹模式的采用范围及必要基点。剩余疑问不再影响方向、范围或验收时结束澄清。
2. 从依赖已满足的工作中选择自做或分派，按下文确定边界、并发和模型。相关小票可由同一 Agent 连续承接；大票只按独立交付边界分工。分派完成条件是目标、修改负责人、允许范围与验收明确。
3. 实现者按“验证与失败处理”修改并验证对应场景。主 Agent 同期推进依赖主线、共享入口、小改动或核验已有交付，不重复子 Agent 的整段调查。
4. 主 Agent 串行整合，聚焦核验关键差异、逐条验收与相关契约，按项目协议记录范围、基点、结论及实际证据。输入因整合改变则重跑受影响验证。符合收票协议才标记完成，再解锁依赖并继续循环；逐票完成不代表 effort 已完成。
5. 整个 effort 全部实现整合、相关验证及资料同步完成后，按“评审”做一次完整双轴审查；尚有未授权批次时保留整体审查待办，effort保持未完成。实现者批量修复发现，主 Agent 按“发现关闭与额外审查”核证据并关闭。完成条件：所有票验收、证据和状态与现场相符，发现已解决或按项目授权裁定，必要检查通过；交付简述结果、证据入口及未验边界。发现影响已完成票时据实调整状态并重新收尾。

常规技术选择、分工和模型升级由主 Agent 自行决定，批次间不重新请求授权。实现授权范围内的可逆本地分支与隔离操作自行安排，遵守用户明确限制和环境权限，不逐次询问。业务口径冲突、范围实质变化、缺少必要授权或经诊断仍无法解决的阻塞才交用户裁定，附证据、已尝试做法和推荐选择。局部阻塞期间推进独立工作。提交、推送、部署和现有服务重启按用户授权执行。

## 动态分派与隔离

并发不设固定数量，也不以填满环境槽位为目标。增加一路须同时满足：依赖允许独立推进，修改区域与契约边界清楚，验证现场可隔离，主 Agent 能及时整合，预计收益能覆盖额外交接及核验成本。没有依赖不等于没有冲突。

同一修改区域只有一个写入负责人。共享文档、接口设计、数据库、浏览器和构建目录安排顺序或隔离；独立只读调查优先考虑并行，小任务直接调用现有工具。主要瓶颈若是同一个外部操作，先解决瓶颈。冲突、重复探索、资源争用或待整合积压出现时，减少新分派、先处理已有结果。

Git 暂存、提交、合并及共享产物验证由主 Agent 串行协调。并行写入确需隔离时使用 worktree，从已验证的集成状态起步；互斥文件可在同一工作区修改，子 Agent 不操作共享 Git 索引。只提交本 effort 的授权改动，收尾清理本任务的隔离现场，保留其他任务与生产资料。

分派携带目标、规格与票指针、修改边界、相关约束及验收要求。动态选模型时使用独立上下文，只补必要裁定，不复制全聊天历史。子 Agent 返回改动摘要、命令与退出码、证据位置、未决风险；主 Agent 核关键结果。扩展分工由主 Agent 统一安排，不默认层层再分派。

同一 Agent 的配置合适且上下文清楚时复用；切换模型、隔离噪声或独立审查时再创建。实现、调查、整合和审查是职责，不各设常驻 Agent。交接复用票和提交指针，只在确需跨会话时持久化必要内容。

## 模型与推理强度

每次创建子 Agent 显式指定模型与推理强度，适用于调查、实现、审查和修复。仅允许 `gpt-6-luna` / `high`、`gpt-6.1-sol` / `medium` 或 `high`。禁止 GPT-6 Astra；不使用 xhigh、max、ultra。主会话沿用用户选定且符合上限的配置，不擅自切换主会话模型。

主 Agent 在上述范围内自主选择与调整子 Agent 配置，以可靠完成任务的总成本为依据：用户介入、等待、主 Agent 与子 Agent 的消耗、核验和返工一并计入。任务类型不对应固定档位；无需先试轻模型，也无需逐次报告选型理由或请求批准。

能力不足时保留已验证结果与关键证据，在允许范围内调整配置；环境故障先修环境。重复失败且没有新证据时主 Agent 接管或缩小问题，不盲试。配置不可用时选受支持的允许配置；无合适配置则报告具体阻塞，不越过上限。

## 验证与失败处理

新缺陷先建立能失败的反馈；已有确定反馈时直接复用，只有反馈不足或原因仍不明时才展开诊断。验证覆盖当前验收涉及的受影响分支及保存、提交或恢复后的稳定状态，高风险边界必要时在隔离现场核实失败能力；普通文档整理不强制 TDD。

极小改动属于普通模式中预期明确、影响局部、复用既有出口且不改变重要数据保障的情况。行为改动默认验证新增行为，以及最近可能受影响的既有行为或失败分支，再运行项目必需钩子；这些断言可以合在一个用例中。纯文字或指针改动采用相应的最小核对，不强制新增测试。相关反馈通过、差异与验收一致且无未决时结束，不默认跑大范围测试或完整双轴审查。

共享契约、金额、权限、写入校验、事务、回滚或既有缺陷保护受影响，或出现相关失败、覆盖不足时，扩大到实际受影响路径并说明理由。高风险小改仍可用普通模式配较强验证；低风险多阶段任务也可能需要整体统筹。项目已有强制检查和有效保障继续生效，不能仅凭改动规模降低它们。

选能覆盖验收的最低成本验证，优先复用项目现有测试：逻辑和接口用对应测试，浏览器验证真实交互。局部 UI 覆盖对应页面、状态和相关宽度，共享组件、样式或契约扩大到受影响路径，业务高风险及发布扩大范围。命令与选集现查项目配置。复用成功项须确认相关代码、输入和环境未变，包括影响选集或预期的票与规则资料；资料同步后核最终输入，只重跑失效或未验证的依赖。执行器仅支持整组选集或广泛签名时，据实处理机器失效；人工复用说明实际未变的依据，不能冒充逐用例缓存。钩子、销号和最终核验复用有效证据。

编辑循环先跑能暴露当前缺陷的最小场景；相关分支稳定后合并运行共享影响与项目要求的发布检查。修改共享调用时一并定位保护它的现有检查，按原契约处理失效的实现匹配断言，保留其缺陷检测能力。数据量、尺寸、主题和页面按各自风险选择代表场景，只有交互依赖才组合成矩阵。后续变化仅使相关证据失效；整理最后的资料与记录后一次核最终输入，避免同一选集因收尾动作反复重跑。

重复验证交给项目选定的确定性测试程序执行，Agent 读取简短结果并处理异常，不逐次重演已固化动线。临时交互探索、定位或失败诊断按任务需要选合适能力，普通跑测试不加载交互操作技能；具体工具、运行入口及适用范围由项目绑定。现有能力不足时回“当次能力发现”，比较、隔离验证后在当前授权内引入。

复用项目的测试准备与收尾方式，保证当前构建、可复现日期及必要数据。写入场景使用隔离数据；浏览器状态独立不代表数据库隔离。独立场景应能单跑且不依赖执行顺序，端口、浏览器和构建目录按上述隔离规则安排。完成后只释放本任务拥有的现场，保留必要失败证据和其他任务资源。

编写或优化浏览器测试时，等待明确的页面状态、焦点或响应，使用所选框架的自动等待与可重试断言；超时先核定位条件、挂载和布局。重资源确有耗时时可复用浏览器进程，页面、上下文及可变数据仍按场景隔离。参考资料须适配项目实际语言和执行器；已有可靠体系继续复用，引入技能或工具须证明本次增量，不能以迁移框架代替解决耗时来源。

隔离验证从已确认完成的输入同步，核实际源与目标的绝对路径，复制失败即停止依赖它的构建或测试。接受结果前核实际工作目录、关键输入与产物来源相符，按项目已有版本标识、文件清单或内容摘要留证；副本或产物来源不符时，排除该结果，修正输入后只复验受影响部分。

布局或外观变动查看相关页面的实际截图，必要时补尺寸断言；生成截图或读到页面结构不等于已完成视觉核验。不默认建立全站截图基线、多浏览器矩阵或每票新增测试。仅将有持续回归价值、能检出实际缺陷的场景固化为测试；关键新断言按风险核实失败能力。

失败先依据证据区分产品缺陷、测试缺陷和环境故障；不足则注明待判定及下一步最小诊断。保留首次失败输出、具体步骤与必要现场，浏览器失败提供截图或轨迹入口，详细证据按需读取。步骤、进程及收尾须有界，未知选择、异常和断言失败返回非零。执行器挂起先诊断期限与环境，不反复修改产品；不用跳过断言、静默重试或迎合当前输出修改预期取得通过。工具的自动修复建议仍须核对规格与实际缺陷。

与本次改动或验收相关的失败须修复并复验。已证明无关的既有失败，保留非零结果、归因证据及现有票或待办中的后续位置，按项目协议判断是否阻塞交付；不自动扩展为无关修复，也不将整个入口报告为全绿。证据不足时仍为待判定，不能按无关处置。

## 评审

累计范围与最终双轴安排适用于整体统筹模式。普通模式按实际风险聚焦核验，必要的专项审查及其发现也按下文关闭。

固定起点与当前集成结果必须能表达本 effort 的完整差异，包含其未提交和新增文件，并排除起点已有及其他任务改动。两轴使用同一范围。调用 code-review 前确认其默认提交比较覆盖该范围；不适用或无 Git 时提供可回溯差异材料，完成同等独立双轴核对，不为适配审查而提交或整理其他任务工作。

每票由实现者自测、主 Agent 聚焦核对。主 Agent 自写的高风险或证据薄弱部分，必要时由独立子 Agent 专项审查。中途审查说明具体风险、限定范围及为何需在后续工作前完成；“工具改动”“共享机制”“高风险”决定深度，不自动触发逐票双轴。

最终完整双轴只做一次：Standards 核项目规范，Spec 核规格与验收，独立并行，配置由主 Agent 按上述模型规则自主选择。基于固定起点与当前集成结果，覆盖新文件、最终差异及跨票关系，只读取相关规范与必要关联；业务部分回读权威定义，技术部分核契约及独有验收。有效机械检查已覆盖的确定性规则不再重复人工扫描。发现给出处、代码位置与具体影响。

完整审查一次收齐两轴发现，按共同影响批量修复；以下规则也适用于普通任务实际发生的审查。最终评审记录只存一份，相关票引用。

### 发现关闭与额外审查

- **实现者修复并自验**：核清同一发现的受影响分支，提供能检出原问题的反馈与修复后证据；通常交回熟悉现场的实现者，由主 Agent 自做的部分由主 Agent 修复。
- **主 Agent 关闭发现**：对照原要求、最终差异和有效验证，确认问题及其影响已解决，或依据项目协议记录不采纳的授权与理由。现有票或审查记录留结论和证据指针；事实性确认、已通过的确定性检查和完成标记由主 Agent 处理。
- **额外审查由具体未决触发**：主 Agent 与现有验证仍无法裁定的判断性问题、已发现的修复风险，或实质扩大到原审查未覆盖的范围。回到审查者前，说明具体问题、受影响差异和现有证据为何不足；只请相应轴或专项审查，无发现且未受影响的轴保持结束。

具体未决已消除、必要验证有效时结束，不因进入下一批或已有修改追加回合。用户要求或经说明确需覆盖扩大的完整范围时，可再做完整审查，按实际范围、原因与回合记录，不以“聚焦复查”掩盖重新扫全量。仍有影响验收的未决则保持未完成。

## 项目适配

- 项目 Agent 入口负责指明规格、票源、业务权威、验证方式、记录与授权规则；按任务触发读取相关资料。
- 具体路径、业务编号、测试命令、票格式、服务与部署限制写在项目文档中，由该项目维护。没有适配文档时从现有入口与配置定位；仅缺少必要信息时询问，不为使用本技能强制新建整套文档。
- 本技能拥有通用调度、个人模型限制、验证策略与评审时机。项目验收、具体验证入口、有效保障和授权边界继续生效；未裁定的实质规格冲突按上文提交用户。

首次在项目接入时，由项目入口指向本技能，统一旧调度指针，按项目协议保留历史记录；不复制本技能正文到各项目，也不在技能中收集各项目的规则。不自动改变其他正在执行的任务。
