# 委派、模型与隔离


每次创建子 Agent 显式指定模型与推理强度，适用于调查、实现、审查和修复。仅允许 `gpt-6-luna` / `high`、`gpt-6.1-sol` / `medium` 或 `high`。禁止 GPT-6 Astra；不使用 xhigh、max、ultra。主会话沿用用户选定且符合上限的配置，不擅自切换主会话模型。

主 Agent 在上述范围内自主选择与调整子 Agent 配置，以可靠完成任务的总成本为依据：用户介入、等待、主 Agent 与子 Agent 的消耗、核验和返工一并计入。任务类型不对应固定档位；无需先试轻模型，也无需逐次报告选型理由或请求批准。

能力不足时保留已验证结果与关键证据，在允许范围内调整配置；环境故障先修环境。重复失败且没有新证据时主 Agent 接管或缩小问题，不盲试。配置不可用时选受支持的允许配置；无合适配置则报告具体阻塞，不越过上限。

## 何时委派

只有存在能独立推进的调查/实现/审查，边界清楚、写入与测试环境可隔离、主 Agent 能整合，而且收益值得分派与回收成本时才委派。数量由可并行工作和整合能力决定，不按票数固定。

每个子任务提供最小必要的目标、范围、权威指针、已有有效证据和输出要求。不要把整个会话、历史报告和包维护手册复制给每个子 Agent；发现必要上下文缺失再补读。返回改动摘要、实际命令与退出码、证据位置及未决风险，由主 Agent 核关键结果。

配置合适且上下文清楚的执行者可复用；需要切换配置、隔离噪声或独立审查时再创建，不为每种职责设常驻 Agent。扩展分派由主 Agent 统一安排，不默认层层委派。出现冲突、资源争用、重复探索或整合积压时减少新分派，先处理已有结果。能力不足则保留已验证成果，在允许范围内调整；环境故障先修环境，重复失败无新证据时接管或缩小问题，不盲试。

## 写入与验证隔离

明确每位执行者可改的文件/区域和不可改的公共内容；共享文件一个写入主人。共享工作区的 Git 暂存与提交串行由主 Agent/既定整合者处理，子 Agent 不并发操作共享索引。

需要工作树时按项目已有隔离方案建立并确认真实基线；不要用 reset/clean 掩盖基线不符或覆盖他人修改。可共享只读资料，不共用有写入冲突的数据库、端口、用户会话或输出目录。

独立审查者只拿共同固定范围、标准、规格和必要上下文，不拿另一审查轴的结论作为答案。实际工具不支持必要独立性时明确未完成，不以主 Agent 自述替代。
