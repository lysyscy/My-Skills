# 委派、模型与隔离


Codex 中每次创建或更换子 Agent 前，按[模型调度总则](codex-model-routing.md)完成本次模型、推理强度与上下文选择，并在实际调用处核参。已读方法可复用，本次派发决定不能省略；用户指定配置优先于主控选择。

## 何时委派

默认由当前 Agent 完成复现、调查、实施和适当验证；小而连贯的任务直接推进。主 Agent 持有用户沟通、关键结果核验与唯一收尾责任，自主判断是否委派，无需用户逐次选择模式。

上下文噪声隔离、独立并行、专门能力或必要独立审查有明确收益，且任务边界清楚、写入与测试环境可隔离、主 Agent 能整合，收益值得分派与回收成本时，才委派。按上下文边界拆分：同一问题紧密相连的定位、修复和测试尽量交给同一执行者；独立调查或黑盒验证可以单独分派。数量由可并行工作和整合能力决定，不按票数或职责固定开 Agent。

每个子任务提供最小必要的目标、范围、权威指针、已有有效证据和输出要求。不要把整个会话、历史报告和包维护手册复制给每个子 Agent；发现必要上下文缺失再补读。返回改动摘要、实际命令与退出码、证据位置及未决风险，由主 Agent 核关键结果。

配置合适且上下文清楚的执行者可复用；需要隔离噪声或独立审查时再创建，不为每种职责设常驻 Agent。扩展分派由主 Agent 统一安排，不默认层层委派。出现冲突、资源争用、重复探索或整合积压时减少新分派，先处理已有结果。派发被宿主并发上限拒绝时，把失败分派转为后台或延后单独补发，主 Agent 同时推进已返回结果的核验收口，不空转等待；前台降并发留作兜底。能力不足则保留已验证成果，在允许范围内调整；环境故障先修环境，重复失败无新证据时接管或缩小问题，不盲试。

## 写入与验证隔离

明确每位执行者可改的文件/区域和不可改的公共内容；共享文件一个写入主人。共享工作区的 Git 暂存与提交串行由主 Agent/既定整合者处理，子 Agent 不并发操作共享索引。

需要工作树时按项目已有隔离方案建立并确认真实基线；不要用 reset/clean 掩盖基线不符或覆盖他人修改。可共享只读资料，不共用有写入冲突的数据库、端口、用户会话或输出目录。

独立审查者只拿共同固定范围、标准、规格和必要上下文，不拿另一审查轴的结论作为答案。实际工具不支持必要独立性时明确未完成，不以主 Agent 自述替代。
