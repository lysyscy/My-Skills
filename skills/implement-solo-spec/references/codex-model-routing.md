# Codex 模型调度总则

在用户明确指定和宿主实际支持的范围内，主控依据任务难度、业务风险、上下文连续性，以及质量、等待时间和消耗自主选择子 Agent 配置，不设固定套餐、模型分工或起始档位。主会话沿用用户选择，不自动修改原生配置。是否委派及工作隔离仍按 [delegation.md](delegation.md)。

每次创建或更换执行者时，在实际派发处完成以下动作；读过本文件不能代替本次选择：

1. **选择。** 同时确定模型、推理强度和上下文模式，在本轮记录或派发说明中用一句话说明任务依据。已有执行者续用时核配置仍适合；不为补配置记录重跑已完成工作。
2. **落参。** 对照宿主当前工具定义，将所选配置写入实际调用参数。需要完整上下文且宿主要求继承模型时，确认继承配置适合并说明理由；采用独立上下文时分别选择模型与强度，不能将 `fork_turns="none"` 误当作已独立选型。省略可指定参数不是选择依据；仅在有意继承且已说明时使用默认。工具不支持的配置明确报告并选择可用方案，不在任务正文声称一次未发生的模型切换。
3. **核对。** 调用前核目标、模型、强度和上下文参数与选择一致；工具返回后核可见的实际配置，宿主未返回的字段保持未核实。发现误配先判断能否保留有效工作，不为修正形式重建全部代理。

压缩、交接或接续时，只在现有任务记录中保留尚未执行的派发决定及理由；恢复后对照当前工具能力重新核参。不默认沿用上一次配置，也不复制整套调度手册或建立长期调度台账。本规则约束主控的派发步骤，不冒称宿主已提供参数强制校验。
