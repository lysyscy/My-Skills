# Codex 子 Agent 模型选型

版本：2026-10-28。Codex 专用；这是个人调度策略，不改变真实付费订阅，也不是官方能力或用量保证。创建或调整子 Agent、处理用户指定的执行者配置，或用户要求切换方案/默认时读取。模型规则与持久默认仅由本文件持有；其他客户端不采用本规则。

## 当前执行者与自动选型

主会话沿用用户在界面或指令中选定的模型与思考强度。手动选择只确定相应执行者的配置，不自动要求或禁止委派；是否委派由 [delegation.md](delegation.md) 按实际收益判断。当前执行者直接完成其能够胜任的完整任务，表格中的职责偏好不限制其能力，也不要求为匹配表格再创建一个执行者。

下表仅用于需要创建或调整的子 Agent 自动选型。用户明确指定某个子 Agent 的模型或思考强度时，指定项优先，未指定项按所选方案与实际模型支持补齐；该覆盖只在用户指定范围内生效。主会话的手动配置不自动成为所有子 Agent 的配置，套餐切换也不更改主会话。

例如：用户已在界面选择 Terra / high 并要求修复局部交互问题，当前 Terra 可直接完成修复与验证；需要独立调查或审查时才按收益委派，自动创建的子 Agent 再按下表选型。用户明确指定该子 Agent 使用 Terra / high 时，沿用指定配置，不以 Pro200 自动起档覆盖。

以宿主可见配置为准；不可见时不猜测、不声称已切换，也不因无法识别模型而要求用户重复声明执行模式。

## 选择与切换

持久默认（手动编辑时只改此块）：

```yaml
package: pro200
mode: daily
```

`package` 仅取 `pro100` / `pro200`；`mode` 仅取 `daily`（日常）/ `ample`（充裕）。Pro100 / Pro200 是策略名称，分别有日常、充裕两档。

- 「切到 Pro100 日常」「切到 Pro200 充裕」：作为当前任务后续阶段的临时覆盖，回报采用的组合；任务结束即退出，不改持久默认。用户指明更窄范围时按该范围执行。
- 「把默认改为 Pro100 充裕」等明确修改默认的指令：只更新上面选择块，沿现有源维护、发布和 Skills Manager 同步流程生效；不在安装副本另存默认。手动切换也编辑维护源的同一块并同步。
- 选择顺序为明确的任务覆盖、持久默认。无有效组合时说明配置缺口，不猜套餐；不按剩余额度、换套餐或使用反馈自动改默认。跨会话接续临时覆盖时，在已有交接中携带组合与退出范围。

按运行时真实支持的模型、推理强度和工具参数显式采用所选组合。不可用时选支持且适合任务的配置并说明差异；无合适配置则说明阻塞。API 可用不等于客户端可用，策略选择不等于模型已切换。

## Pro100

保留此前已发布方案的日常/充裕语义；本节的 Astra 排除及较低起档仅限 Pro100。

| 工作 | 日常 | 充裕 |
| --- | --- | --- |
| 机械提取、整理、规则明确的检查 | `gpt-6-luna` / `high` | `gpt-6-luna` / `high`；确需较多判断可用 `xhigh` |
| 简单界面操作、截图核对 | `gpt-6.1-terra` / `medium` | `gpt-6.1-terra` / `high` |
| 已定位局部修复、需要判断的视觉核验 | `gpt-6.1-terra` / `high` | `gpt-6.1-terra` / `high`；复杂视觉可用 `xhigh` |
| 常规代码实施、范围明确的技术分析 | `gpt-6.1-sol` / `medium` | `gpt-6.1-sol` / `high` |
| 疑难定位、复杂业务、跨模块工作、关键审查 | `gpt-6.1-sol` / `high` | `gpt-6.1-sol` / `xhigh`；极难局部才用 `max` |

Pro100 排除 Astra；日常不自动使用 `max` 或 `ultra`。

| 工作 | 日常 | 充裕 |
| --- | --- | --- |
| 完整研究、常规实施与收尾 | `gpt-6.1-sol` / `xhigh`，默认主力 | `gpt-6.1-sol` / `max`，主要研究与实施；简单任务仍按职责选合适的小模型，不硬套 Sol / max |
| 复杂实施、疑难定位、跨模块修改和关键审查 | `gpt-6.1-sol` / `max`，直接选用，不要求先让 `xhigh` 失败 | `gpt-6.1-sol` / `max` |
| 重要架构决策、全局路线、难回退的重大取舍 | `gpt-6-astra` / `high`；全局路线或难回退的重大取舍用 `xhigh`，基于已核事实和候选直接参与 | `gpt-6-astra` / `xhigh`；关键决策与必要独立反例挑战，数据正确性、保存语义或大范围替代存在关键不确定性时按需采用，不设为每批必经 |
| 界面操作、视觉核验、明确局部 UI 修复 | `gpt-6.1-terra` / `max` | `gpt-6.1-terra` / `max` |

Pro200 自动选型的 Terra 与 Luna 两档均固定 `max`。工具或 harness 的实际能力优先；若不支持 `max`，停止该配置的分派并报告用户期望与可用能力，不静默降档，也不声称已执行 `max`。

## 共同执行边界

四种组合默认 Standard；Fast 独立按速度需求且工具支持时选择，充裕不默认 Fast。`ultra` 不常规自动选。不保证精确等额度，不用 API 单价推算订阅用量，不凑额度或模型比例，不为用额度重复审查，也不建立自动预算控制器或后台监控。

按实际推理难度与业务后果判断风险，而非文件数。先区分证据、权限、连接不足与推理不足；前三者处理实际缺口，不能靠升模型解决。直接选适合的执行者，不强制先试便宜档或走 Luna → Terra → Sol 流水线。默认一个合适执行者，仅有独立收益才分工；既有委派收益、合理并行、隔离、独立审查与生命周期规则仍适用，不为调度额外增加审查或双跑。

子任务或阶段变化时重新判断后续子 Agent 的配置；正常运行中的任务不打断。在新建子 Agent、执行者空闲或新阶段，按实际工具能力指定 `model` / `thinking`（或宿主对应参数），调整仅对后续生效。工具不能切换时，保留已核事实、候选、有效证据及未决点，按现有交接机制交给可用的新执行者；不伪称已热切换。长任务仍按现有上下文和交接机制分批，不为节省少量用量反复迁移上下文。
