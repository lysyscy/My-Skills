# 已授权任务的实施与唯一收尾

## 边界与初查

先确认本次目标、只读/实施边界、项目规则与保存授权。只读任务只交付分析。普通技术选择由 Agent 决定；业务口径冲突、实质扩大范围、必要权限不足才交用户。外部提示词点名先读清单时，与所属技能正文要求的参考链取并集后再开工，不把提示词清单当穷尽。

读取项目绑定、现行业务及实际入口。创建或变更资料落点、受管理产物，或归属/生命周期不清时，按下节来源定位同版本 setup-solo-workflow/references/document-layout.md；同源同版本已读且仍适用的内容可复用。项目接入、专项迁移、复杂运行产物、共享资源退出或分类/保留有具体风险时，执行随该技能分发的 workspace_check.py 相关范围；缺口只阻塞依赖动作，不在业务项目复制规则或检查器。简单任务无相关产物或变化时，不制造 effort/run、空目录、归档或无输入变化的治理检查。普通改动核受影响范围；全面查漏或同类缺陷修复，先从需求、页面/命令、操作注册表及后台任务交叉列清功能和入口，逐项标已核、未核、不适用或已退休，并绑定代码与验证依据。按风险选生命周期反例，覆盖关联入口和恢复/重建等共享边界，不把全部组合强制套到每个小任务。标题、引用存在或截断片段不能替代正文；清单已对齐、关键风险有判据后停止泛搜，随后只补明确空项。

没有规格或票不阻止明确小改动；确需跨批接续时才保存必要范围、基线与指针。任务记录引用现行业务，不复制一份要同步的正文。

## 规则来源与定位

本核心及跨技能资源属于 lysyscy/My-Skills；技能名和技能内相对路径只是文件定位信息。技能内相对引用以本次真实入口/引用文件为基准，不从业务工作目录猜测。跨技能先用宿主提供的真实路径或已核实安装来源找到同来源的主人，不假设技能目录相邻；同名多来源或同来源多副本而不能确定版本时报告歧义。

可读取可见且获准的同来源、同版本中央库或固定执行快照；完整源仓可读固定版本的技能内参考，普通任务不依赖包根工具，也不自动安装修复。资源必须在所属技能内且真实存在。长任务沿已固定 SHA/内容摘要与规则，变化不能冒充原基线；找不到旧内容则暂停依赖步骤或取得切换授权。来源未知、资源越界、缺失或固定摘要变化只阻塞依赖动作，不伪造读取或启动包同步掩盖。

## 读取与工具输出

先用文件清单、标题或命中行缩小范围，再读相关分支的必要完整正文；相同内容与版本已读则复用。工具发现先按服务和动作筛选，只取名称与短描述，选定后再读接口详情。输出截断时按所需范围续读，不重发整批材料；仍须核必要正文完整性。

长命令将详细输出写入本轮既有logs/reports，显示启动信息，按需读进度、末尾摘要或失败上下文；无输出本身不等于挂起。完成后核原始退出码，日志与摘要不代替执行结果。沿用现有读文件和进程工具，不为分页或进度另建包装器。

## 路径与风险

先明确用户要得到的结果、被验收的版本与行为、数据含义、隔离和授权。这些条件不能因工具便利而改变；临时目录、进程、端口、构建副本和工作树是实现手段，不损失未保存状态、不影响他人工作且上述条件不变时，可以自主替换或等价重建。

路径受阻、反复失败或支持性工作持续膨胀时，重新判断该步骤是否仍是必要依赖，比较修复、复用健康能力、等价重建或省去无用步骤的成本。继续尝试须有新证据、可检验假设或明确依赖理由；否则重选路径，确实受阻才报告阻塞。换路仍须通过相同验收，不能换掉待验分支、有效测试或真实数据口径。

遇到其他失败，先判断关联性。本次造成或阻塞验收的继续调查；独立问题不自动转为修复、立票或新项目。未知归属的资源保持受保护，不因此成为维护义务；已无用途的本任务临时资源按生命周期退出。

首次确需运行环境、依赖/版本/配置变化或失败指向环境时，按上述来源定位同版本 setup-solo-workflow → references/environment.md 并读取；以项目实际入口检查或在授权内准备。已有证据且输入未变时复用，不触发全机盘点或包同步。

默认普通改动：可在一个范围内独立交付与验收就直接推进。跨批依赖、累计集成或项目既定统筹要求出现且采用授权明确时，读取 coordination.md。高风险可以仍是普通改动，必须加强验证，而不是机械增加调度流程。

创建任何子 Agent 前必读 delegation.md。没有清晰独立收益就由主 Agent 完成；不按票数固定开 Agent。

发现现有能力不够、反复手写工具性代码或不熟悉接口时，读取同来源 improve-workflow/references/capability-selection.md。已有机制足够则直接使用；不因此启动复盘或安装。

## 实施与文档影响

按真实需求做最小完整变更，不扩大为无关重构。修复缺陷先得到可验证的失败反馈；可复用已经能稳定复现的失败，不重复制造同一红灯。新增外部行为按明确公共接口做小步反馈，预期来自需求/独立样例而不是复制实现计算。

每次改变外部行为、术语、接口/资料主从关系、操作/验证方式或入口时，核相应现行资料是否过时；有影响再读同来源 setup-solo-workflow/references/document-maintenance.md 并同步唯一正文及必要引用。每次授权改动或阶段完成时，处理直接相关的失效段落、文件、状态与实际消费者，包含前序会话遗留的相关材料；父 effort 活动不是推迟收尾的理由。没有影响不制造日期、流水或空台账变更。

本流程默认只参考 Matt 的相应方法，不完整运行另一套 implement/TDD/收尾。用户要求完整原版时保留其确认及必需步骤；与当前权限/项目约定冲突时明确冲突，不静默删步骤后仍称完整调用。

仅消费 TDD 方法时保留公共边界、red-before-green、逐个行为切片及有效缺陷保护。已有公开接口与已确认验收足以选技术测试接缝时，由 Agent 记录选择及覆盖边界并直接验证；接口承载的业务含义未决、实质范围变化或缺失授权才需用户决定。完整调用 TDD 时沿用其确认要求。纯文档调整不强制 TDD。

## 面向使用者的判断与沟通

界面改动先确认实际使用者、具体动作及误判风险；由需求持有界面结论，方法文档不另复制结果清单。旧行为与修改后的实际验证读 [verification.md](verification.md) 的界面分支；本次涉及重要界面内容取舍、用户阶段验收或交互预览时，读 [human-collaboration.md](human-collaboration.md)。明确小改与普通技术/视觉调整沿原流程推进。声称实测前必须真实测量，重要删减在交付时明确说明。

先调查规格与环境已能回答的问题，只询问用户独有事实、业务选择和授权缺口。需裁定时用具体情景、选项代价和推荐说明；同轮问题与选项编号不得歧义，跨轮回答要核对应关系。不同数字先核对象、时间和口径，不直接当矛盾；明确局部修改不扩大成重设计。

## 基础验证

从项目真实配置取得命令和隔离要求，按真实规模、已确认用法、发生可能、失败后果及维护成本选测。先核现有检查能否证明本次验收与最近相关旧行为/失败分支；足够就复用，真实验收缺口或值得维护的回归风险才补最小用例。纯重构优先复用，默认不新增持久测试；低风险、可逆且已有充分覆盖的改动，可用现有检查或直接观察完成验证。不按改动或票数新增测试、跑全量或做变异验证。重要新规则、严重缺陷及数据/权限边界须有能稳定检出问题的回归保护，优先复用或补强现有用例。

用最接近实际行为且成本合适的接缝验证；mock 浏览器只证明其模拟范围，不能代替数据库约束、事务或权限验收。记录选测依据、覆盖边界与未验风险；扩大验证由新变化、失败或未决风险触发。纯文档修改检查语义、引用和实际消费者，不进入无关应用测试或 TDD。必要的保存、提交或恢复动作完成后，验证对应的稳定状态；这些动作未改变被测输入时复用有效结果。

涉及权限、资金或业务写入、事务/回滚、共享契约、原始缺陷保护、浏览器状态、真实数据/环境或失败归因时，读取 verification.md 的相关分支。项目已有更严格验收继续生效。

验证结果只对实际内容、输入、环境、测试选择和预期有效。它们未变且覆盖足够时复用；变了就重验受影响范围。未执行、超时、非零退出或未知失败不能说通过；不能跳过保护用例、改预期或换口径换取绿灯。

## 自查、独立审查、关闭发现

实现者按覆盖清单做局部核验，同类缺陷先核完整入口集合和适用边界。每次交付前由Agent主动判断审查深度，包含自固定基点以来累计未审的改动及整合风险；同一对话、分票、新开对话与是否独立审查分别判断，不等用户提醒。

- 自查足够：范围清楚、局部可逆、已有验证足以覆盖后果且无实质未决风险。
- 定向独立审查：有明确局部风险或不确定接缝，独立检查该问题即可补足信心。
- 完整独立双轴：累计跨模块或共享机制改动存在相互影响，或者关键金额、权限、写入/恢复语义涉及多入口且仅局部检查不足；由Standards核项目约束、Spec核原需求与验收。不能只凭涉及金额一词或文件数机械触发。用户明确要求的审查及coordination.md最终双轴要求继续生效。

在已有票或回执说明选择、理由、固定基点及实际范围，不新建审查台账。需要完整评审时，待授权范围整合、调用者和夹具同步、必要检查通过后统一进行；包含本轮拥有的已提交、暂存、未暂存及新文件，核覆盖清单及未核项，不只核最后一次提交。审查者从原需求、约束和实际代码独立判断，不以实现者结论代替证据。

审查同样按「基础验证」判断真实风险；仅有理论边界或启发式建议，不自动要求新增测试或阻塞交付。证据足够且没有新变化、失败或实质未决风险时即止。主 Agent 将每个实质发现对应到修复证据、明确不采纳理由或未决阻塞。复用范围、基点及依赖仍有效的审查结论，最终覆盖新增差异与尚未审过的整合风险；修复后由原审查者定向复核受影响部分。已关闭且未受影响的轴保持关闭，只有新增差异影响其判断时重开。

独立审查需要真实独立上下文；主 Agent 自查不能换名冒充。测试通过、独立审查通过与人工业务验收分别据实表达。

## 唯一收尾

主 Agent 核完整授权范围、必要验证、受影响现行资料、实际引用和未决发现。只保存一份必要证据，其他记录用指针；微小任务可只在最终回执说明，不强制建文件。

按项目资料生命周期处置本轮结束材料：有效知识及理由归现行主人；历史去向按 document-layout 的 Git-only 默认及具名例外，核活动目录、当前状态和引用已退出或更新。effort 全部范围完成且没有活动未决项时，在同一次收尾实际移出活动目录、补历史状态并更新现行引用；删除空文件和空目录。不能仅签 done、留一句“待归档”，也不能因目录叫“持续主线”永久例外；确有后续活动范围只保留验收、复测、范围或依赖所需最小材料，明确用途、主人及退出条件；不因父任务活动而保留已退出用途的文件或段落。已有授权内的归档直接完成；归属、范围或权限确有缺口时保留现场并询问，列为未完成收尾，不能先宣称 effort 已结。无资料需要处置时不造归档件。

本轮写过 Agent 消费的文档时，核实际读取并应用了 writing-for-agents 和项目文档约束，复核完成判据、信息层级及真实消费者；文档方法正文回 setup 所属 document-maintenance.md，不另抄规则。未完成的发布、安装、备份或归档按各自验收记为待办，不用代码测试通过代替。

公共文档/状态与共享 Git 暂存、提交由唯一负责人串行处理。按项目已有授权保存，不自动获得提交、推送或部署权限；Git 无远端时，允许已授权提交并明确“未执行推送”，不报交付失败。

创建了受管理资源，就按同来源 setup-solo-workflow/references/document-layout.md 核清归属、当前用途和结束去向；资源用途结束、运行结束与用户验收等待分别判断。主预览仍供用户验收时保持有效，本任务临时验证用途结束且无活动消费者/独有未保存状态时自主退出。已触发的目录检查按相关范围执行 run-closed/closed，非零或去向不明保持对应收尾未完成；这不要求停止仍有用途的全部服务。阶段完成不触发整个 effort 退出，无相关产物不造空目录或治理记录。固定目录与保留期限仍归 document-layout.md。默认只清理由本任务拥有且不再需要的资源；专项清理按明确授权，保留他人修改、活动证据和未决失败现场。策略拒绝清理时报告遗留位置与原因，不换工具或路径绕过。

最终回执限定到实际核验范围，分别报告实现、已退休事项、缺陷和未验证项，再报保存/提交/部署状态。票终态、编号有引用、已有测试或评审通过各自只证明其覆盖内容，不能推导产品完整或绝无遗漏。无远端时明确“已提交；本项目无远端，未执行推送”，不创建远端、不套用个人包管理事务；不因回执出现新提交号反复生成自指回执提交。
