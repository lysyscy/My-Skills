# 已授权任务的实施与唯一收尾

## 边界与初查

先确认本次目标、只读/实施边界、项目规则与保存授权。只读任务只交付分析。普通技术选择由 Agent 决定；业务口径冲突、实质扩大范围、必要权限不足才交用户。

读取项目绑定和与本次目标直接相关的现行事实、代码/资料消费者及实际验证入口。标题、目录、JSON 概览和截断片段不能代替必要正文。能够定位改动点、关键约束、可观察验收及主要风险后，停止全面探索。

没有规格或票不阻止明确小改动；确需跨批接续时才保存必要范围、基线与指针。任务记录引用现行业务，不复制一份要同步的正文。

## 规则来源与定位

本核心及跨技能资源属于 lysyscy/My-Skills；技能名和技能内相对路径只是文件定位信息。技能内相对引用以本次真实入口/引用文件为基准，不从业务工作目录猜测。跨技能先用宿主提供的真实路径或已核实安装来源找到同来源的主人，不假设技能目录相邻；同名多来源或同来源多副本而不能确定版本时报告歧义。

可读取可见且获准的同来源、同版本中央库或固定执行快照；完整源仓可读固定版本的技能内参考，普通任务不依赖包根工具，也不自动安装修复。资源必须在所属技能内且真实存在。长任务沿已固定 SHA/内容摘要与规则，变化不能冒充原基线；找不到旧内容则暂停依赖步骤或取得切换授权。来源未知、资源越界、缺失或固定摘要变化只阻塞依赖动作，不伪造读取或启动包同步掩盖。

## 路径与风险

默认普通改动：可在一个范围内独立交付与验收就直接推进。跨批依赖、累计集成或项目既定统筹要求出现且采用授权明确时，读取 coordination.md。高风险可以仍是普通改动，必须加强验证，而不是机械增加调度流程。

创建任何子 Agent 前必读 delegation.md。没有清晰独立收益就由主 Agent 完成；不按票数固定开 Agent。

发现现有能力不够、反复手写工具性代码或不熟悉接口时，读取同来源 improve-workflow/references/capability-selection.md。已有机制足够则直接使用；不因此启动复盘或安装。

## 实施与文档影响

按真实需求做最小完整变更，不扩大为无关重构。修复缺陷先得到可验证的失败反馈；可复用已经能稳定复现的失败，不重复制造同一红灯。新增外部行为按明确公共接口做小步反馈，预期来自需求/独立样例而不是复制实现计算。

每次改变外部行为、术语、接口/资料主从关系、操作/验证方式或入口时，核相应现行资料是否过时；有影响再读同来源 setup-solo-workflow/references/document-maintenance.md 并同步唯一正文及必要引用。没有影响不制造日期、流水或空台账变更。

本流程默认只参考 Matt 的相应方法，不完整运行另一套 implement/TDD/收尾。用户要求完整原版时保留其确认及必需步骤；与当前权限/项目约定冲突时明确冲突，不静默删步骤后仍称完整调用。

仅消费 TDD 方法时保留公共边界、red-before-green、逐个行为切片及有效缺陷保护。已有公开接口与已确认验收足以选技术测试接缝时，由 Agent 记录选择及覆盖边界并直接验证；接口承载的业务含义未决、实质范围变化或缺失授权才需用户决定。完整调用 TDD 时沿用其确认要求。纯文档调整不强制 TDD。

## 基础验证

从项目真实配置取得命令和隔离要求，不从全局规则猜测试命令。行为变更至少覆盖受影响的新行为及最近相关旧行为/失败分支，并保留项目要求的检查。纯文档修改检查语义、引用和实际消费者，不进入无关应用测试或 TDD。必要的保存、提交或恢复动作完成后，验证对应的稳定状态；这些动作未改变被测输入时复用有效结果。

涉及权限、资金或业务写入、事务/回滚、共享契约、原始缺陷保护、浏览器状态、真实数据/环境或失败归因时，读取 verification.md 的相关分支。项目已有更严格验收继续生效。

验证结果只对实际内容、输入、环境、测试选择和预期有效。它们未变且覆盖足够时复用；变了就重验受影响范围。未执行、超时、非零退出或未知失败不能说通过；不能跳过保护用例、改预期或换口径换取绿灯。

## 自查、独立审查、关闭发现

实现者在过程中做局部自查和必要测试，仅针对具体未决风险安排定向独立审查。需要完整评审时，待同一已批准交付范围全部整合、调用者与测试夹具同步、必要检查通过后统一进行；普通任务是否需要完整双轴由项目风险要求决定，统筹任务的最终双轴遵循 coordination.md。

主 Agent 将每个实质发现对应到修复证据、明确不采纳理由或未决阻塞。复用范围、基点及依赖仍有效的审查结论，最终覆盖新增差异与尚未审过的整合风险；修复后由原审查者定向复核受影响部分。已关闭且未受影响的轴保持关闭，只有新增差异影响其判断时重开。

独立审查需要真实独立上下文；主 Agent 自查不能换名冒充。测试通过、独立审查通过与人工业务验收分别据实表达。

## 唯一收尾

主 Agent 核完整授权范围、必要验证、受影响现行资料、实际引用和未决发现。只保存一份必要证据，其他记录用指针；微小任务可只在最终回执说明，不强制建文件。

按项目资料生命周期处置本轮结束材料：有效结论归现行主人，有独有价值的过程保留来源后归档，核活动目录、当前状态和引用已退出或更新。已有授权内的归档直接完成；归属、范围或权限确有缺口时保留现场并询问，列为未完成收尾，不能先宣称 effort 已结。无资料需要处置时不造归档件。

本轮写过 Agent 消费的文档时，核实际读取并应用了 writing-for-agents 和项目文档约束，复核完成判据、信息层级及真实消费者；文档方法正文回 setup 所属 document-maintenance.md，不另抄规则。未完成的发布、安装、备份或归档按各自验收记为待办，不用代码测试通过代替。

公共文档/状态与共享 Git 暂存、提交由唯一负责人串行处理。按项目已有授权保存，不自动获得提交、推送或部署权限；Git 无远端时，允许已授权提交并明确“未执行推送”，不报交付失败。

只清理由本任务拥有且不再需要的临时进程、端口、工作树和产物，保留他人修改、活动证据和未决失败现场。策略拒绝清理时不得换工具、删父目录或改路径绕过；报告遗留位置与原因。

最终回执只说实际变更、验证及未验证部分、保存/提交/推送状态、必要未决项。无远端时明确“已提交；本项目无远端，未执行推送”，不创建远端、不套用个人包管理事务。无需同步修改多个摘要，不因回执出现新的提交号反复生成自指回执提交。
