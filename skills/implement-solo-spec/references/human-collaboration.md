# 人机协作与阶段验收

仅在本次涉及重要界面内容取舍、用户阶段验收或交互预览时读取。常规实施、验证、环境和收尾仍由各自已有方法负责。

## 用户参与的边界

用户决定业务含义、重要信息与功能范围、实质使用流程和授权。Agent 先查需求、现有界面和环境已能回答的问题，再就真正未决项提供具体情景、代价和推荐。已确认选择及明确要求不重复确认。

新页面、整页改版或明显改变使用流程时，在实际实施前对齐必要内容和重要取舍；普通间距、对齐、组件内布局及可逆视觉细节由 Agent 自主处理并观察结果。当前任务已有批准范围或样例时直接沿用。

采用已有上游澄清或设计方法，先定位实际安装入口，只读取当前需要的参考。完整调用某个 Skill 时遵守其真实流程；局部参考不能冒称完整调用。外部原版由原渠道维护，个人包只保存必要衔接与本人的偏好。

## 阶段验收

只在会改变下一步选择、需要用户业务判断或已规划的验收点邀请用户查看。复用现有计划、规格或票，不因每次构建成功而制造一个新审批点。

展示时说明本次看什么、对应的实际版本、Agent 已验证什么、仍有哪些需用户判断。内部实现细节留给执行记录，不进入产品界面。

技术检查通过、视觉确认、业务验收和部署分别表达。等待用户判断时，继续不依赖该判断的工作；不把未决定的业务语义先实现成事实。

## 主预览

主预览是规划中向用户开放的验收入口，展示该验收范围对应的完整可操作版本；它不等同于主分支，也不自动成为生产服务或永久常驻服务。

到达预定验收点前，Agent 完成必要的功能和视觉检查，再提供入口和实际加载版本。用户仍需查看时保留其用途；不能把单条命令结束或本次回复结束当作应当关闭的依据。

当前项目或任务已有入口、负责人、版本与保留约定时，直接沿用；需要跨会话接续时只补已有记录中的必要信息。

## 临时预览

临时预览用于调查、局部试验、对照和验证，由创建者负责。它不自动成为人工审批点，也不能以局部样例可运行推导整体验收完成。

用途结束、结论已保留且不存在活动消费者或独有未保存状态时，自主停止本任务持有的临时实例并按既有生命周期退出产物。确实不清楚用户是否还需查看、共享依赖是否存在或归属是否属于本任务时，保留必要现场并提出具体问题。

停止服务与删除数据库、源码、工作树是不同动作。保留重要代码、数据和恢复依据，不因“临时”标签取得额外删除权限。

## 遇阻与退出

保持验收版本、数据含义、隔离和授权不变时，临时承载可以重建或替换。发现旧服务异常只判断其是否为当前目标的实际依赖，不自动修复全部旧环境。

资源退出在 Agent 实际工作和收尾节点执行；未配置自动化时，不承诺离开会话后仍有后台清理。必要生命周期检查仍回 document-layout，技术验证仍回 verification，唯一收尾仍回 execution。
