# 已授权范围的跨批统筹

仅在执行核心判定需要统筹且已有采用授权时使用。沿已批准的范围与关键取舍安排批次、分派和整合，不为普通技术调度重复询问用户，也不将扩大范围当作调度权。

## 固定累计范围

开始时记录范围、采用依据、真实 Git 固定点，以及已存在的未提交和新增文件范围。延续任务复用原记录，不重置起点。文件清单处理保留空格/中文等真实文件名，Git 枚举使用无歧义形式。

最终审查覆盖从起点到完成的实际累计变更，包含本范围内未提交与新增内容，并排除起点已有且不属本任务的改动及其他任务改动。不能只看最后一批、最后一个提交，也不能仅用 three-dot HEAD 差异漏掉工作区/新增内容。基线内容不完整时先补证，不声称覆盖完整；不得为适配审查而提交或整理其他任务工作。

## 共同输入

按实际项目票协议参考 Matt 规格与票模板；拆票的输入兼容不等于采用统筹。

- 共同规格记录范围、业务权威指针、已确认取舍、票索引与真实依赖、共享接合边界、验证入口、整体完成条件和授权。
- 每票具备完整且可独立验收的用户路径、阻塞关系、状态、规格指针、相关业务引用、独有验收及验证类型。发布前核范围闭合、验收可判、依赖无环、指针有效；影响方向、范围或验收的未决先裁定。
- 采用记录、已交付接合与必要未决事项存入共同规格或所属票，按项目协议更新。具体实现细节留给实施者，已有事实通过指针复用。

## 任务图与批次

以阻塞关系、共享写入边界和独立验收划分工作。能够形成完整纵向切片就不拆成只做数据库/只做界面的假独立交付；必要大范围机械迁移可采用扩展、迁移、收缩，但每批的可验证性要清楚。

共同规格及票记录已确认范围、权威来源、必要验收、阻塞关系和授权；发布前核依赖无环、验收可判与指针有效。未满足的前置是阻塞，不自动扩展本次实施范围。

每票按 execution.md 的基础验证选测，可引用覆盖本票验收且输入、环境与预期仍有效的共享测试证据；票独有行为或保障缺口才补独有验证，不把独立验收等同于每票新建测试或重复整套检查。

从已就绪任务选择当前批次；并行前读取 delegation.md。每批局部验证与自查后由主 Agent/既定整合者串行合并公共状态，更新原任务记录；符合项目收票协议才标完成。已存在范围/证据不复制到新的平行台账。当次只授权单票/批次时只完成该范围及必要接合。尚有未授权批次时保留整体未完成及最终审查待办，不把局部完成报为全项完成。

## 最终独立双轴与收尾

满足 execution.md 的完整评审前提后，对同一累计范围统一完成 Standards 与 Spec 两个独立并行审查轴，均遵守 delegation.md 的配置限制，不能共享结论互相暗示。宿主无法提供所需独立上下文、并行能力或合规模型时，如实报告该项未完成，不以串行自查或放宽模型限制冒充原要求已满足。

标准轴区分项目明确规则和有待判断的启发；规格轴核遗漏、错误实现及扩范围。个人流程适配未提交范围，不谎称未经改动的原版 code-review。

主 Agent 按 execution.md 复用有效结论、关闭发现和统一收尾。测试、审查、人工验收及部署的状态分别报告。

接续时仍用原规则/授权基线；个人技能更新不自动更换在途任务依据。
