# 已采用的跨票统筹

只在普通实施入口判断需要且采用范围明确时读取。项目拥有票协议、业务规则和隔离命令。

1. 固定共同规格、依赖图、验收与授权，记录真实起点及范围内已有修改。续接复用原记录；最终审查覆盖累计提交、未提交与新增内容，排除他人工作。
2. 按真实依赖和可独立验收的用户路径分批；核依赖无环、指针可用、验收可判。不要把没有独立交付价值的前后端拆分当成并行切片。
3. 只分派就绪且可隔离的工作，遵守宿主调用约束。给每个执行者明确写入区域；共享文件、索引、合并和公共状态由主控串行处理。工作树须核真实基线，不用 reset/clean 掩盖差异；数据库、端口、会话和输出不可冲突共用。
4. 主控核返回结果与相关验证，再整合并更新原票。已有证据仍适用时复用；独立验收不要求每票重复全套测试。局部受阻时继续已授权且无冲突的工作，不扩大范围或绕过拒绝。
5. 对同一累计范围完成 Standards 与 Spec 两个独立并行审查轴；分别提供项目标准与规格，不互传结论。宿主无法满足独立性或配置时明确未完成，不以自查替代。修复后只复核受影响发现，最后统一收尾。
6. 接续保留原业务、验收、权限和已采用版本。新模板发布不自动切换在途任务基线；需要切换时在原任务记录明确采用点。
