# UniGetUI 软件更新

本机安装位置为 `D:\software\UniGetUI`。使用同目录的 `uniget.exe`，命令以[已安装版本的官方 CLI 文档](https://github.com/Devolutions/UniGetUI/blob/v2026.3.3/docs/CLI.md)和本机帮助为准。

## 检查

1. 在当前登录用户的交互式桌面会话运行 `uniget.exe status`，检查 `running`、版本与会话，优先复用正在运行的 UniGetUI。沙箱内返回 `running: false` 时，先在同一桌面会话复核，不能据此启动第二个实例。确认该用户会话中未运行时，由技能从该用户的交互式桌面启动已登记的 `D:\software\UniGetUI\UniGetUI.exe`，等待 IPC 就绪及软件更新扫描完成后再读取候选；不能确认会话归属或启动、扫描、读取失败时，记录具体原因并标记「UniGetUI 待检查」，继续其他项目。检查不改变开机启动项、自动更新、忽略规则或来源设置。
2. 用 `manager list` 核实实际可用的后端，用 `package updates` 读当前候选。必要时用 `package installed` 或 `package details` 补安装信息。列表未完成或来源报错时标记相应缺口，区分「无候选」与「未查到」。
3. 在总报告单列 UniGetUI 候选。每项给出**包 ID、管理器、来源、安装范围、已装版本、精确目标版本**。同一个安装实例由 UniGetUI 返回时，合并工具链检查里的重复项。同名软件来自不同渠道或安装范围时，保持各自身份，归属无法确认的项只供核对。登记版本与实际解释器不符时，先核安装范围、可执行文件和消费者；将登记与实装分别报告，同名的 uv 管理安装按其自己的渠道核对。

## 逐项更新

1. 用户点选后再次核对该包的身份、安装来源、范围、当前版本、目标版本及是否已有更新在执行。目标发生变化、管理器无法锁定目标版本，或需要改来源、关闭在用程序、提权、重启时，将该项留给用户决定，继续处理其他独立项。更新 UniGetUI 或本批依赖的管理器时单列，避免中断正在执行的批次。
2. 对符合条件的每个包调用 `package update`，传入已核实的 `--id`、`--manager`、`--version` 及后端支持的 `--source`、`--scope`。可用 `--wait false` 取得操作 ID，再用 `operation wait --id <操作ID> --timeout <秒>` 查到终态。单次选择只覆盖已点选的项目，执行入口只用单包操作。
3. 分别查最终操作状态和实际安装版本。以同一安装实例的实测版本判断实际变更；操作失败或提示与实测不符时单独记录差异和原因。排队、超时、失败、待重启或版本未核实分别记录。等待超时时先查原操作，避免重复入队。按[更新收尾](completion.md)处理本次受影响入口及残留；由包管理器负责的卸载或清理沿其官方入口，不手动删除未知安装目录。按[状态与记录](status.md)回写选定批次。

## 归属

- Codex 附带的 CLI 和 PowerShell 由桌面宿主管理。独立版 Codex CLI 已卸载，重新登记后才纳入检查。独立 PowerShell Preview 按自身预览渠道核对。Skills Manager 本体由用户手动更新，受管技能走[技能规程](services.md#技能更新)。
- UniGetUI 的 npm、pip 等候选只代表各自已识别的安装实例。项目锁文件、服务 `.venv` 和浏览器共享缓存仍走各自规程。
