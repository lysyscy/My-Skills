# 批次计划与报告

在对话中按目标列组件新版检查和当前版本依赖检查。注明来源、时间、范围及未验证原因。暂停项注明恢复条件。

## Batch Plan JSON

获准输出 HTML 且存在候选时，使用 UTF-8 JSON 和新输出路径。在技能目录执行 `python scripts/render_report.py batch.json report.html`。脚本用 Python 标准库，生成单文件离线报告。无候选时在对话交付检查结果。

### 新批次使用 `schema: 2`

| 层级 | 字段 | 约束 |
|---|---|---|
| 顶层对象 | `schema` | 整数 `2`。 |
| 顶层对象 | `batch`, `caption` | `batch` 为有效的 `YYYY-MM-DD` 日期。`caption` 为快照时点或范围说明。 |
| 顶层对象 | `groups` | 非空分组数组。 |
| 顶层对象 | `current`, `paused` | 字符串数组。分别写确认无更新的记录和暂停项。 |
| 顶层对象 | `decisions`, `operations`, `notices`, `followups` | 四个数组。各自无记录时填 `[]`。 |
| 分组对象 | `name`, `items` | 分组名和非空候选数组。 |
| 候选对象 | `id` | 本批唯一，匹配 `^[A-Z][A-Z0-9-]*[0-9]$`。 |
| 候选对象 | `target`, `current`, `candidate` | 字符串，依次写目标、当前版本、精确候选版本。 |
| 候选对象 | `ready` | 布尔值。`true` 表示精确版本与验证条件已明确，可进入验证。 |
| 候选对象 | `details` | 非空对象，键和值均为字符串。 |
| 候选对象 | `actions` | 非空动作数组。每个动作包含 `when`、`work`、`verify`。 |
| 候选对象 | `notice` | 可省略。出现时用一句话写用户会受到的具体影响。 |
| 候选对象 | `source` | 可省略。出现时为带主机名的有效 HTTPS URL。 |

### 决定、操作、提醒与待办

- **需要你决定**（`decisions`）。确实有取舍要用户选，或某项操作需要新增授权时才填。用 `target` 和 `action` 说清要决定什么。`options` 至少有两个对象，每个包含 `label` 和 `impact`，写明选项及执行后的影响。选项名去掉首尾空白后须不同。`recommendation` 是推荐选项从零开始的整数下标。`waiting` 只写在等这个决定的具体操作。其他已获授权、能独立开展的工作继续。
- **需要你操作**（`operations`）。用 `target` 和 `action` 写用户要亲手完成的一步，用 `waiting` 写完成后才能继续的操作。
- **你留意一下**（`notices`）。每条是一句涉及多个候选或整批的用户提醒，写明对用户的直接影响。单个候选的提醒用该候选的 `notice`。
- **我来处理**（`followups`）。每项用 `target` 和 `status` 写跨候选或跨批次的目标与已知情况，用非空 `actions` 写接下来的操作和核对办法。

决定和用户操作可填 `candidateId`，必须对应同批候选的 `id`。报告会链接到该候选。决定区位于候选表前，按 `decisions` 计数。空数组显示「本批无需你决定」。通过对话给出决定或授权，HTML 只供查看。

每个动作的 `when` 为 `now` 或 `after-authorization`。已有权限开展的工作标 `now`，需要获授权才能开展的工作标 `after-authorization`。`work` 写要做哪一步，`verify` 写要看什么结果来判定完成。候选表显示工作和时机，详情里可查核对办法。按当次授权执行，`ready` 只描述验证准备情况。

在 `details` 中记录两类检查结论、版本来源、验证基准、影响范围、适配与验收。共享环境列相关消费者、锁的归属及覆盖范围。候选未就绪时在详情写原因。证据不足的事实标「未验证」，把可做的核对写入候选的 `actions` 或整批 `followups`。

### 旧批次与输出校验

归档计划省略 `schema` 或使用整数 `1`，可沿用原 JSON。旧计划使用 `pending` 字符串数组，候选沿用 `risk`、`action`、`safe` 和 `ready`。报告保留旧候选的风险和建议动作，`pending` 原文显示在「旧批次备注」。新版决定区和决定数只由 `schema: 2` 的 `decisions` 生成。

除标为可省略的字段外，字段均必填。字符串须含非空白字符。禁止未知字段和重复 JSON 键。校验失败时退出码为 `2`，不生成文件。输出路径已存在时同样退出，保留原文件。

交付前查看实际报告，核对分组、编号、版本、详情和来源链接。确认需要用户决定、需要用户操作和未就绪候选各自对应计划里的记录。

## 更新结果

按本批编号对账，列出原版本、精确目标、各层实测状态、适配和验证结果。说明范围变化、已回退和仍待办的项。待办写明原因和可继续的条件。附上已生成的报告或批次引用。
