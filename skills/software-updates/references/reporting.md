# 汇报格式

检查和候选用本地 HTML 报告，应用结果用 Markdown 表格。标明核对日期，每个组件一行，沿用候选编号。区分本地安装、项目环境、生产部署、服务加载和用户已处理。安装器提示和实测分别记，实际版本以实测为准。

## 检查

按具体项目或服务分组，UniGetUI 桌面软件、本机工具链、受管技能各自成组。候选默认展开，主表固定为「编号、组件、已装版本、目标版本、影响范围、状态」。展开单行查看来源、基准、两类检查结论、适配和验收。待确认与未完成检查列在候选之后，已完整核实的无更新集中折叠。[检查范围](targets.md#检查范围)中暂时停查的目标放在页末「暂停更新」区域；已退役的目标从报告省略。

将本批证据整理成 UTF-8 JSON，在任务的临时工作区保存输入，输出到用户可打开的报告位置。使用技能目录中的 `scripts/render_report.py <批次.json> <报告.html>`。生成器使用 Python 标准库，报告可直接打开。每次用新的输出文件名。

- 顶层：`batch` 为北京时间批次日期（YYYY-MM-DD），`caption` 写检查时点或历史快照及范围，`groups` 为候选分组数组；`pending`、`current`、`paused` 为字符串数组，无记录时填空数组。
- 分组：`name` 为项目、服务或渠道名称，`items` 为候选数组。
- 候选：`id` 是本批唯一编号；`name`、`installed`、`target`、`scope`、`status` 填文字；`ready`、`security` 填布尔值；`details` 为字段名到文字的映射；`source` 可填官方 HTTPS 链接。
- `details` 至少写「组件新版检查」「当前版本依赖检查」「来源与基准」「适配与验收」。项目填写可复核的完整提交或锁 SHA-256，桌面软件写包 ID、管理器、来源和安装范围。多包候选写精确版本清单，缺证据时写明范围与原因。
- 只有精确目标和验证范围已定、能进入验证的候选才设 `ready: true`。在对话中收到整批更新或指定编号的指令后，先对照本批报告及当时证据，再按验证与应用规程复核。
- 交付前打开报告，核分组、版本、折叠状态及候选编号。原始查询和可重建输入按任务的产物规则处理。

下表给出每个组件的证据字段，主表之外的字段放入行详情。


| 编号 / 组件 | 声明或锁定 | 实际安装或运行 | 组件新版检查 | 当前版本依赖检查 | 新版功能或修复 | 项目适配 | 状态 / 来源 |
|---|---|---|---|---|---|---|---|

每个组件都交付「组件新版检查」和「当前版本依赖检查」两格结论，并分别注明核对时间与来源。共享环境标明联合解析覆盖的组件和消费者，可汇总候选数量，再按包展开差异。

依赖差异较多时用下表；单项可直接放入总表对应格。

| 所属组件 / 共享环境 | 依赖包 | 实装 / 本地 pin | 上游约束及锁的归属 | 精确稳定候选 | 结论 / 来源 / 未查原因 |
|---|---|---|---|---|---|

上游精确锁定写「上游精确锁定，保留」及来源；自有项目 pin 有新版时写「需更新本地 pin」及验证条件。必需预发布依赖单列，不计入稳定版更新数量。

未查到、来源不可达、扫描未完、解析失败或仅查直接依赖时，必须在对应表格单元格说明原因和覆盖范围。依赖随组件捆绑时写清发行包渠道和独立核查边界。只有完整检查后才填「无候选」；不适用时说明依据。

UniGetUI 单独分组，写包 ID、管理器、来源和安装范围。候选写拟应用环境、基准提交或锁 SHA-256。

## 更新

| 编号 / 组件 | 原版本 → 目标版本 | 实际版本 / 状态 | 新版功能或修复 | 项目适配 | 加载与功能验收 | 入口迁移 / 残留去向 / 待办 |
|---|---|---|---|---|---|---|

分别使用「候选通过」「已同步」「已更新」「已部署」「已加载」「受阻」「已回退」「演练通过」。每项写实测证据及剩余待办。共用工具的安装、消费者迁移和旧版去向分别记；仅验证或发布文件时，运行状态仍以运行证据为准。按[更新收尾](completion.md)写清已迁移入口、已清理项目及保留材料的用途和释放条件；引用各服务 README 和验收回执，不复制其具体保留规则。

## 功能、适配与补丁

- 新版功能以官方说明或已核实的上游提交为准。无公开说明时注明。依赖的变化与项目实际新增功能分别说明。
- 项目适配用「无需适配」「已适配」「待适配验证」或「待用户决定」，写清影响、兼容性必改、可选优化和实际动作。
- AstrBot 插件行写上游设置入口和默认值、本机有效设置、新版 WebUI 变化。另列补丁表。检查时列预计影响；更新或回退后列实际保留、重放、适配、上游替代或无补丁，以及证据和备份位置。

| AstrBot 插件 | 补丁影响或处理 | 验证 | 加载 / 回退 |
|---|---|---|---|

用户要求整体流程图时，画出检查、选择、隔离验证、授权分流、应用、失败回退、复核和回写。专项支路按需展开。
