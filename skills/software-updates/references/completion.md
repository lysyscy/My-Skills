# 更新收尾：验收、入口迁移与残留清理

用于已授权更新的收尾，或用户单独要求的升级后验收、入口迁移、残留清理。只读检查仍停在报告；更新、生产启停、业务数据和技能分发沿本批授权，不由收尾步骤扩大范围。

## 定位本批规则与消费者

从目标项目或服务的 README 读取当前版本、实际运行入口、验收与回退方式、备份及资源清理规则；README 指向的专题文档仍由项目持有。软件安装器和包管理器负责的目录，按其正式卸载/清理入口处理。技能只持有通用方法，不复制服务版本路径、保留份数或专用恢复命令。

识别本次更新影响的消费者与入口：运行进程、服务启动参数、计划任务、管理脚本、快捷方式/启动器、安装或任务注册脚本、环境/解释器、备份恢复入口及已部署副本。只查实际相关项；更新源文件和更新已注册入口是两个结果，例如改任务安装脚本不会自动修改现有定时任务。

## 迁移与验收

1. 把获准切换的消费者和入口指向目标版本，并同步负责重新生成这些入口的配置或脚本。沿用原启动策略；已停用的服务或任务保持停用，除非本批授权恢复。
2. 分别确认磁盘实装、入口解析、进程实际加载和关键功能。按改动影响执行项目必需检查，复用输入与预期仍适用的已有结果；健康端点或安装器成功不能代替受影响的记忆读写、导入、构建等功能验收。
3. 迁移备份入口时，通过迁移后的真实入口完成一次备份，核成功结果及现行轮换规则；已有有效证据可复用。回退方式变化时验证相应恢复路径，按项目边界在隔离目标进行；普通运行入口迁移不自动要求整套恢复演练。
4. 切换失败或验收未通过时，按项目规则回退并核实际恢复情况。保留未决故障所需的最小现场；明确哪些结果已证明、哪些仍受阻，不把文件已替换报告为全部完成。

## 残留处置

验收通过后，在本批授权范围内处理失去用途的旧虚拟环境/运行时、旧 UI、下载包、候选锁、测试日志、隔离库和升级快照。删除前确认它们属于本批、无运行或配置消费者、没有独有数据、且不再承担有效回退或待验收用途。先迁移依赖，后删旧目标；版本名旧或目录存在时间长本身不构成删除依据。

- 日常备份按各服务 README 和已有轮换逻辑保留；升级专用快照按本次回退需要释放，不默认进入永久保留。当前锁、配置、凭据和正式数据留在其维护位置，不把临时升级目录当唯一来源。
- 数据库用该服务的数据库管理接口清理，保留正式库及仍被启动代码引用的基础库。有活动连接时先查消费者；不强制断开未知客户端或直接删除数据库物理文件。
- Windows 文件清理先核解析后的绝对路径属于获准目录，使用精确路径；未知文件、并行任务、未解决失败和仍有回退用途的材料保持原状。
- 仍需保留时，在既有任务记录写明用途、路径和释放条件；条件满足后收尾清理。不默认永久保留上一版，也不为所有项目另设统一等待天数或保留份数。

## 完成与记录

按[汇报格式](reporting.md)分别记录版本、实际加载/必要功能验收、入口迁移和残留去向。仅这些适用项已完成且实质问题关闭时报告更新收尾完成；合理保留的回退材料列清释放条件，未获授权或尚未解决的项保留待办。

具体服务规则和当前入口更新到其 README 或其指定文档；跨项目更新记录写本技能维护源的 `references/status.md`，引用服务回执而不复制另一份现行服务规则。释放可重建中间文件，保留最小验收结果。
