# 更新收尾

按调用方的维护文档定位实际消费者、验证入口、回退方式和清理规则。核对本批授权和结果，复用输入与预期仍适用的验收证据。

## 选定本批检查

按实际改动选检查，以本批授权、调用方口径和项目必跑项为准。用户已确认更新或重载时，记录用户确认。有版本疑点时，读一次实际入口。

| 更新影响 | 检查到这里即可 |
| --- | --- |
| 调用方指定只安装的上游软件，或无自有补丁的普通插件 | 记录安装器或包管理器的成功结果。 |
| 普通上游技能 | 读技能管理器的更新结果。部署位置变动时核对宿主实际使用的路径。 |
| 独立 CLI 工具 | 从平时用的终端入口跑一次版本命令。 |
| 项目小范围依赖更新 | 选受影响的入口。类型声明跑类型检查，构建工具跑构建，文档库用一份样例，网络库用一次模拟请求，Go 依赖先确认能编译。 |
| 改到自有补丁、钩子或服务接口 | 用正常入口试一次受影响的功能。同一条操作能覆盖同时更新的组件时合并检查。 |

选定检查通过后结束。出现与本次变更相关的新失败或明确覆盖缺口时，再补能解释它的检查。

## 收尾步骤

1. **迁移入口。** 对获准切换的消费者核对源配置、启动参数和已注册的实际入口。同步负责重建入口的配置。沿用原有启停策略，恢复停用项须有本批授权。
2. **验收实际使用。** 按选定范围记录[观测状态](../SKILL.md#三个契约)。隔离演练和正式服务分别记录。获准切换正式服务后，至少核对正式入口的版本和健康状态。若迁移了备份或恢复入口，按调用方规则验证相应路径。应查而未验的事项保留待办。
3. **处理失败。** 按维护规程回退并核实际恢复结果。保留定位故障或回退所需的最小材料。
4. **处理残留。** 核实失去用途的旧入口、安装和中间产物属于本批，且无消费者、独有数据或回退用途，再按授权使用维护方的清理入口。对保留材料记录用途和释放条件。
5. **交付结果。** 按[报告规则](reporting.md#更新结果)归账。适用的加载、功能验收、迁移和清理都有证据后，报告收尾完成。

## 记录

仅在「检查并记录」或明确授权包含记录的更新收尾中，使用调用方已声明的入口。按其记录规则写回 Observed State，按事件口径追加 Event Log。按调用方声明的规则和授权刷新本地看板，并核实际输出。缺少某项入口时在对话说明现状与未写入的结果。
