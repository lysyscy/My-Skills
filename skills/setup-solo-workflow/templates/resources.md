# 运行资源模块

接入时按目标实际消费者布置，setup负责固定版本工具的部署升级；方法与接口见setup的references/artifact-lifecycle.md。项目开发命令使用随仓实现，负责登记、消费和退出。可弃中间件用系统临时目录；确有保留用途的开发证据放`.artifacts/runs/<id>`，原生缓存沿所属工具；仓外根需显式配置。旧生产者和固定运行沿原目录与期限，不自动接管。

- 原始输入、正式数据与交付、可复用源码和必要业务依据不进入通用按期删除。代码归维护源，裁定归正式记录，不重复保留整套现场。
- 用途结束后释放可重建的临时副本、候选、日志和截图。只为具名下一动作、未决验收或有效回退保留最小材料，并记录退出条件；仍在用的资料归正式入口。
- 仅主动登记的产物接受自动清理。相关成果保存/交付、必要核对完成、永久依据归位且无活动消费者时，按组开始计时；不等父任务结束，查看文件不续期。
- 显式选 work/evidence/permanent；work 结项即到期，证据按具名用途选截止日或30/60天。已有登记和项目特例保原期限。
- 已核可弃的开发失败在诊断结束后释放；只为具体后续用途留下最小失败证据。未知结果、独有资料及身份不明的运行继续保护。
- 未决、待验收或恢复用途局部暂缓删除，记原因、解除条件，30天复查只提醒。解除后未起算者开始计时，已起算者取原到期与解除后7天的较晚日期。
- 每日检查、错过补跑，成功静默；异常和复查到期首次/实质变化提醒，重复去重。实际调度与通知未验证时不称后台已生效。
- 删除前核真实绝对路径、链接、归属、内容变化和活动使用。使用生产者共同遵守的互斥机制；不明则保留。符合条件后直接删除，不另设回收期，不承诺恢复。
- 清理失败单独报告并重试，保留原测试/构建/发布结果与退出码；显式清理未完成仍非零。新输出无法安全建立时在执行前停止该写入。
- 数据库基线、来源、版本及幂等回执沿业务机制；备份、在用构建及工具缓存沿原管理器。Git忽略不等于可恢复。
- 项目实际配置：[受管输出区、已安装工具入口、register/lease/close命令、永久材料主人、每日执行与通知渠道]。未解析占位符不算已接入；旧材料须另行具名核实与授权。无项目任务只有在实际个人运行区已登记、入口可用时采用；未接入则说明并保留现状，不因本模板假定接入或调度已完成。

任务文件退出与运行产物结项分别布置：在项目收尾入口给出实际安装的 scripts/task_files.py 命令，限定本任务目录与散置票、固定已保存提交，处置后用 --closed 核残留及仓内引用。有效知识先归现行主人；具名活动依赖和独有未保存资料保留。检查只读且不判断删除授权，不放进每次提交钩子，不因采用新登记产物而漏掉任务文件核查。
