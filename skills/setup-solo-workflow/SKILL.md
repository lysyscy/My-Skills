# 接入与更新项目规则

先确认目标项目集合、接入或更新范围及授权。分析请求只输出差异建议；不扫描所有目录后推定都可更新。模板是布置输入，日常任务读取项目或宿主已采用的内容。

1. 读取目标的真实入口、项目事实、已有修改、安装来源和已采用版本。复用其 CONTRIBUTING、规范及专题指南，不为标准目录名创建重复正文。
2. 选用 [模板清单](templates/README.md) 中必要模块；从项目代码与真实配置取得命令、数据目标和消费者。原件、凭据和服务状态不复制进模板。
3. 首次接入明确文件主人；更新比较旧模板、新模板与项目现状。保护项目适配和本地修订；冲突先列出，不整文件覆盖。已有采用记录只保来源和版本，不另建平行台账。
4. 显示将新增、替换、删除的规则、适用范围与影响，按用户已批准内容执行；尚未批准的规则变化保持候选。相同输入再次更新应没有变化。
5. 先准备项目与宿主部署内容，再切换入口。核链接、实际加载和相关检查；活动任务保持原基线，切换需在安全边界明确采用点。
6. 分别报告源模板、项目采用和宿主加载结果；一个项目更新不代表所有目标完成。保存、发布与安装按当次授权。

新建或改变环境时读 [环境接入](references/environment.md)；决定新产物落点时读 [目录设计](references/document-layout.md)；文档职责调整读 [文档职责](references/documentation.md)，维护文本读 [文档维护](references/document-maintenance.md)，专项迁移读 [迁移](references/document-migration.md)。这些是 setup 的接入方法，不是每次开发的必读链。

用户明确接入共享记忆时读 [记忆接入](references/memory-adoption.md)。Hindsight 保留经验、偏好和决定背景，不替代项目规则、用户授权或确定性检查。

产物生命周期接入与通用工具配置见 [产物生命周期](references/artifact-lifecycle.md)；包括无项目受管运行区，接入不自动清理旧材料或安装调度。
