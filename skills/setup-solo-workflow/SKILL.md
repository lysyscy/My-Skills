# 接入与项目文档治理

用户要求新建或初始化项目时，同批建立固定目录与生命周期绑定；已有项目只处理用户要求的接入、绑定修复或专项整理。先遵守本次只读/写入及保存授权；只读只产出分析，不写绑定或迁移。个人技能包的维护授权不授权修改项目，也不覆盖本次只读限制。

## 先定位真实需要

读取当前宿主入口、项目现行资料入口、活动任务、验收与隔离配置，以及 Git 工作区和索引中与本次接入有关的状态。优先沿已有指针定位，足以确定主人、缺口与权限后停止全面探索。

有现成有效配置就复用；事实自己查，普通技术落点按规范决定，不重新询问已确认偏好。业务定义冲突、实质扩范围或必要授权缺口才提交用户。

接入或新建本机 Python 项目时，依赖声明放项目 `pyproject.toml`、精确版本由 `uv.lock` 锁定、环境放项目 `.venv`；默认 Python 3.15，兼容例外写明。用 `uv sync` 同步、`uv run` 执行；项目包留在项目环境，uv 下载缓存可以共享。

接入涉及运行时、依赖准备或环境配置时，读取 [environment.md](references/environment.md)，复用既有管理器并验证共享与项目隔离；有效配置保持原位。

新项目按 [document-layout.md](references/document-layout.md) 固定每类资料与产物的位置、创建入口和结束动作；开始任务、产生输出、运行/任务收尾时读取其中「工程文件与各类产物」及「创建、运行和结束」。老项目不在一次普通接入中顺手搬迁；目录统一需要专项迁移清单。没有内容不建空目录、词汇表、ADR、票或台账。

## 建立最小绑定

修改文档前读取 [document-maintenance.md](references/document-maintenance.md)。只在首次确定资料位置或新建类别时读取 [document-layout.md](references/document-layout.md)。

绑定只记录：个人规则来源及所属技能内资源、项目事实的权威位置、实际验收/隔离/保存机制的入口、必要项目例外。把本技能随包分发的scripts/workspace_check.py接到开始与收尾入口；paths定位，active/run-closed/closed分别核落点、运行退出和任务退出。不要复制全局规则、命令表和业务正文。

普通已授权实施，指向 lysyscy/My-Skills → implement-solo-spec → references/execution.md；这是读取普通参考，不是隐式调用 implement-solo-spec。跨技能定位按 execution 的“规则来源与定位”核真实入口、所属来源与固定版本，不假设技能物理相邻。创建任何子 Agent 前，必须读取同来源的 references/delegation.md。

Matt 配置按实际安装和项目选择复用。默认参考其 issue-tracker 与领域布局契约，不启动另一轮完整访谈；用户明确选择原版流程时，说明并保留原版要求的确认和副作用边界。找不到原版，不声称已调用。

## 专项迁移

只有用户要求文档目录治理时读取 [document-migration.md](references/document-migration.md)。先给迁移、归档、删除分开的整体清单及恢复依据；获批后执行。新发现的独有信息、活动资料或不明归属材料不擅删。

## 验收与结束

验证实际指针可达、既有选择及原件/索引受保护、必要资料有唯一主人、没有重复或空产物；生成入口及.gitignore使用固定分类，落点错误与未退出活动目录的隔离反例须被收尾检查拒绝。已有绑定完整且输入未变时，重复接入应无实质差异。

不启动无关产品实现、应用测试、安装、提交或推送。保存动作按项目授权，回执区分工作区保存、提交和推送；有 Git 无远端时仅跳过推送。

仅在修改接入机制或调查接入失误时读取 [setup-evaluation.md](references/setup-evaluation.md)；普通接入不运行整套演练。只有实际准备维护个人包或发现本次所需规则的来源缺口时，才按相应权限处理包检查，不每个新会话自动同步。

保存与现场处置由当前任务唯一主人按授权完成；只释放本任务无接续用途的现场，保留失败证据。策略拒绝清理时保留目标与原因，不换工具、删父目录或改路径绕过。
