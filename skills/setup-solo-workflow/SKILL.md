# 接入个人开发工作流

让用户集中处理需求、功能和人工验收，由 Agent 维护与改动相关的目录、资料和执行现场。输入为用户指定的项目；输出是后续 Agent 能直接遵守的仓内入口。沿用 Matt 原版技能，个人方法与项目绑定分别维护。

用户要求接入时执行；已接入项目的日常任务由仓内入口引导，通常无需再次运行本技能。

## 新项目与老项目

项目入口接好[包操作的新会话同步条件](../improve-workflow/references/package-operations.md)：首次使用个人方法时检查并同步本机源一次，保护已有改动和运行中规则基线。用户要求复盘并优化个人方法时指向 [improve-workflow](../improve-workflow/SKILL.md)，普通功能任务继续原入口。通用维护方法保留单一主人，文档写作约束（含稳定规则在前、动态内容在后）引用文档维护约定，不向每仓复制正文。

先核项目的票源、状态和领域资料布局；已有有效配置或等价约定直接复用，不重新完整运行 Matt setup。新项目缺少配置时，按 Matt 原版完成必要配置，再建立长期维护与验证入口。随后从 `grill-with-docs` 开始需求澄清，再进入 `to-spec`、`to-tickets` 与实施。需求规格、术语、决策和票随相应阶段产生；接入时标明尚未创建资料的约定落点，不提前编造内容，也不因名称不同重建词汇表、ADR 或票源。

老项目先识别并复用现有配置，确需补齐或变更时使用 Matt 原版处理相应配置；本技能补文档维护与验证的缺口，必要时调整关联活文档与指针。保留票源、历史与未完成任务；规则冲突要落实明确适用范围，既有任务保持原授权。历史整体搬迁、检查退休和测试体系迁移按实际改造范围另行授权，不作为基础接入的固定动作。

## 接入过程

1. **定位现有约定。** 核指定工作区、已有 Agent 入口、当前任务与其他修改；按当前接入动作定位标题，再读取票源、业务权威、文档生命周期、验证与授权的相关章节，复用已读事实。只核本次涉及的完成标记是否与验收及未决裁定冲突，矛盾按项目协议纠正或留在现行待办，接入本身不代替功能验收。直接查配置确认测试入口，区分已有资料和后续阶段才产生的资料。完成条件：现行主人、必要缺口和允许范围已定位，状态矛盾有明确去向即停止调查；后续仅补变化，不遍历全部开放票或历史验收。
2. **复用基础配置。** 已有票源、状态词汇与领域资料布局直接复用；确需补齐 Matt 配置时按已安装的 `setup-matt-pocock-skills` 原版完成。缺少该技能时沿用项目协议，仅补本次必要绑定，不为接入安装整套工具或修改上游技能。读取实际安装目录、链接目标及引用资料，确认本次采用的个人维护源可达；安装记录不能代替当前宿主核验。常规文件命名和指针选择由 Agent 在现行约定内决定；业务分歧、授权缺口或实质范围变化才需要用户裁定。完成条件：每类必要资料有一个可访问的入口，既有约定没有被重复创建。
3. **建立持续文档维护。** 读 [文档维护约定](references/document-maintenance.md)，把所需的项目落点接到现有文档；缺少承载处时再建一份简短适配说明。现行需求须有稳定的活位置，与 effort 规格和历史票分开；复用已有权威，没有时约定简短的需求文档或 README 的需求章节，后续产生真实内容时再建立。已有同等规则只保留原主人和指针，不逐条复制通用约定。采用个人通用方法时，入口须明确要求在生成或修改文档、以及任务收尾时读取该资源，再按本仓绑定操作；只注明方法的维护源不等于接好读取条件。确保普通 Matt 技能执行时也会维护资料。完成条件：后续执行者能确定新资料放哪、谁负责同步、何时封存及如何恢复工作，无需用户临时规划目录。
4. **接好验证入口。** 项目说明提供验证程序、场景选择、隔离数据和服务授权的入口；命令和选项从现行配置查。已有可靠验证直接复用，本次只补入口和必要操作说明，测试体系迁移另按实际需求实施。浏览器探索优先复用已连接的扩展或内置浏览器；重复回归由现有测试程序执行，写入验证使用隔离数据。尚无应用或测试入口的新项目，标明现状与后续建立时机。完成条件：实现者知道现有验证能力、实际操作约束与缺口。
5. **接好个人执行约定。** 项目入口按条件指向 [implement-solo-spec](../implement-solo-spec/SKILL.md)：普通任务读“普通改动”和“验证与失败处理”；拆票或按票接续读“输入与分批接续”；任何阶段创建子代理前独立读“模型与推理强度”。章节引用不启用整个 effort 调度；用户明确采用的 effort 才按其执行循环与评审节奏推进，可整体或按授权批次实施。项目只绑定输入、证据与采用记录位置，保留具体验收、有效保障和授权；通用方法重复改为条件指针。按任务记录既有串行、隔离等限制的适用范围：接入不改变旧任务授权，旧任务限制也不自动延伸到新采用的 effort。完成条件：普通任务、拆票接续、子代理配置和 effort 实施各有清楚入口，没有叠加的默认要求。
6. **核入口并交付。** 查看实际改动，核入口指针、权威位置、历史保留和工作区范围；先同步受影响的活说明，再按最终输入选择现有相关便宜检查，缺少检查时核真实文件与链接。按当前授权与项目保存方式保存接入改动；使用版本管理时核本次新增或修改的项目文件均被记录，含新建的指针目标文件，并确认其他修改保持原状。交付区分已写工作区、已提交或按项目方式保存、待授权保存，尚未保存的部分说明影响与下一步。重新接入已完成的项目时，仅补实际缺口。完成条件：现行入口能到达已有资料，后续资料的约定落点与未决项清楚，保存状态可核实，本任务临时现场已按文档维护约定处置，既有任务与他人改动保留。新项目可以从 grill-with-docs 开始，老项目可以继续需求或实施；简述接入结果与必要未决事项。

## 接入边界

个人维护源拥有跨项目方法；仓内文档只拥有本项目的权威资料、目录、票协议、验证现场与授权绑定。保持现有 Agent 入口文件和章节位置，在其中更新条件指针；已有 AGENTS.md 或 CLAUDE.md 时不为本技能再建第二套入口。

每项新增规则要解决已知摩擦，并有明确执行者与触发时机。普通功能任务只维护受其影响的资料；全仓盘点、工具退休、历史搬迁按另行授权处理。有效保障继续生效，无法证明无用的检查不在接入时删除。必要前置检查通过与用户实际少操心是不同证据，交付时分别说明。

接入与常规资料维护在当前授权范围内完成。项目已有必须审批的结构操作仍按其协议处理；先准备具体改动与影响，避免让用户裁定抽象目录方案。提交、推送、部署和生产服务操作按用户授权执行。
