# 接入个人开发工作流

输入为用户指定的项目；输出是后续 Agent 可遵守的仓内入口。Matt 原版拥有基础配置，个人包拥有通用方法，仓内只维护项目绑定。日常功能任务沿用已接好的入口。

## 先定位，再按缺口展开

按本次只读或已授权维护动作分流；新会话首次使用个人方法，按[包操作的新会话同步](../improve-workflow/references/package-operations.md#新会话同步)核本机源与安装一次；运行中任务保持固定规则基线。读取本次实际采用的[文档维护约定](references/document-maintenance.md)。

先核指定工作区、已有 Agent 入口及未提交改动；复用本会话已读且来源未变的事实。老项目使用下表核必要绑定，新项目也先查已有或等价配置。表是本轮定位工具，结果回既有主人，不另建接入台账。

| 必要事实 | 最小调查入口 | 何时继续查 |
|---|---|---|
| 工作区与当前工作 | 实际目录、版本状态、活动规格/票入口 | 归属不明、当前状态或保存基线有矛盾 |
| 资料主人与生命周期 | 入口指针及命中章节 | 缺主人、引用失效、活需求与历史范围冲突 |
| 票源、状态、领域布局 | 现有配置或项目约定 | 缺配置或用户要求变更 |
| 验证与现场 | 配置中的检查入口、测试准备/收尾接口 | 隔离、服务授权或反馈能力不明；此时读相关实现 |
| 权限与职责 | 当前授权、角色与保存约定 | 执行者或适用范围冲突 |
| 个人方法可达性 | inspect 的实际安装反馈、所需引用及章节标题 | 目标缺失、来源变化或本次要改执行语义 |

先用文件清单、标题或入口导入关系定位路径，再读相关章节。安装检查、配置和已读正文能回答的问题直接复用；缺失路径沿实际引用查找。只为建立方法指针时核目标与章节存在，改变其执行语义才读相应正文。读历史规格先选适用范围、状态与相关当年裁定，已足以判定冲突时结束；其后验收过程只按具体追溯问题读。长文件先定位并选段，连续语义或明确缺口需要时才扩大。测试内部按验证缺口读；后续仅补变化。

首轮批量读取为每个文件选所需章节或短预览，未定位范围的长文本优先用[包操作的 read 限量入口](../improve-workflow/references/package-operations.md#材料读取与结构校验)，其他读取工具显式选段。继续读取服务于尚未回答的具体问题；窗口截断不表示已读完整。

必要事实有证据、缺口与允许范围明确、涉及的状态矛盾有去向时，结束调查并补齐绑定。出现新冲突仅重开受影响项；保留其他已核结论。

## 补齐绑定

1. **基础配置。** 票源、状态和领域布局有效时直接复用；缺失或确需变更时按已安装的 `setup-matt-pocock-skills` 原版处理相应配置。没有该技能时沿用项目协议，补必要绑定。保留历史和活动工作，冲突写清适用范围；普通目录和指针选择由 Agent 完成，业务分歧、实质范围变化和授权缺口交用户裁定。
2. **文档维护。** 先核现行正文、目录职责与实际读取者；发现同一事实多处维护、工程正文混入宿主记忆或历史被当现行规则时，按[文档维护约定的“目录与规则职责”](references/document-maintenance.md#目录与规则职责)收敛并核机器消费者。已有清晰有效布局直接复用，不为接入新建分类模板。更新已有 AGENTS.md / CLAUDE.md 的条件指针；生成/修改文档及任务收尾时必须读取文档维护约定，结合仓内绑定操作。复用现有承载处，缺少时才建简短适配说明；只写项目主人、职责、现场和必要长期例外，通用方法用条件引用。当次演练、读取核验或同步豁免留交付/运行记录，长期入口保持通常条件。现行业务需求保持稳定活位置，effort 规格和历史票引用它；尚未产生的资料只约定落点。后续执行者应能确定何处更新、谁同步、何时封存与如何接续，普通 Matt 任务也能命中维护入口。
3. **验证。** 绑定现有检查程序、场景选择、数据隔离及服务授权；命令/选项回配置，现场接口足够时停止阅读测试实现。已有可靠反馈直接复用；新项目没有能力时标明现状与建立时机。浏览器探索复用已连接能力，重复回归使用现有测试程序。自动检查未被钩子/CI承接可记为具体缺口，是否补齐按实际改造范围决定。
4. **执行路由。** 条件指向 [implement-solo-spec](../implement-solo-spec/SKILL.md)：开工读“普通改动”判断实施路由，并读“验证与失败处理”；拆票/按票接续读“输入与分批接续”；任何阶段创建子代理前独立读“模型与推理强度”并显式配置。完整调度按该节核采用授权，仓内只绑定输入、证据、采用范围与授权来源的记录位置，保留项目角色、关票责任、验收与授权；既有任务保持原授权，旧任务限制按其适用范围生效。复盘个人方法时指向 [improve-workflow](../improve-workflow/SKILL.md)。

接入完成后，新项目按需求进入 `grill-with-docs` → `to-spec` → `to-tickets` → 实施；老项目继续当前阶段。接入只建立入口，后续真实内容随阶段产生。历史整体搬迁、检查退休、测试迁移和产品实施各按实际任务授权，继续保留有效保障。

## 一次收尾核验

受影响的活说明同步完后，集中核最终差异：必要指针可达，主人唯一，项目例外保留，历史/其他修改未受损，尚未产生的资料有约定落点。选择覆盖本次差异的现有便宜检查，缺少时核真实文件与链接。已验证的相同输入与环境复用证据；变动、失败或未覆盖项才重查。普通文档接入使用链接/差异等反馈，应用验收另按实现范围执行。

保存与现场处置沿文档维护约定及当前授权。交付区分写入工作区、已提交/按项目方式保存和待授权保存；Git 未跟踪或 intent-to-add 文件仍可能只存在当前工作区，后续 worktree 的实际基线须单独核实。提交、推送、部署与生产操作遵循任务授权。

完成条件：入口可达、实际缺口已补或有明确去向、冲突范围明确、保存状态可核实，本任务临时现场已处置且其他成果保留。简述结果与必要未决项；重复接入满足条件时直接结束。

修改本技能的接入行为时，按[接入场景验证](references/setup-evaluation.md)验证受影响路径；普通项目接入沿上述检查即可。
