# 接入场景验证

只在修改接入行为或调查已发生的接入失误时使用。普通项目接入按 SKILL.md 收尾，不运行整套演练。

使用包内 `tests/setup_fixture.py prepare --root <本轮临时目录> --skill <固定版本 SKILL.md>` 建立隔离项目。每个版本使用独立目录；比较旧版与候选时采用相同原始请求、夹具和 Agent 配置。向执行者提供原始任务、固定技能和必要材料，不透露预期答案、疑似问题或修复结论；需要独立子代理时先读个人源的模型约定。

原始请求：“为这些项目接入个人工作流，保留项目既有选择和其他修改；仅做工作流与文档接入，交付保存状态，不启动产品实施、提交、推送或生产服务。”

| 场景 | 原始材料 | 验收 |
|---|---|---|
| 已配置老项目 | 既有票源、状态、领域文档、检查配置与角色 | 复用主人，建立缺失读取条件与验证绑定，保留有效规则 |
| 规则冲突 | 当前需求与旧角色的规格指针/复位方式不一致 | 关联真实任务规格，保留他人修改与角色责任；冲突有明确适用范围 |
| 未提交资料 | 已修改需求、未跟踪附件、intent-to-add 文件 | 原件逐字保留，新增指针可达，保存状态与未来 worktree 基线据实区分 |
| 重复接入 | 已有完整入口及绑定 | 复用原文件和协议，无新增镜像、目录或无意义差异 |

执行者用夹具的 `read` / `inventory` 读取演练文本；read 可选行范围或 `--headings`，默认 2000 字符、`--limit` 上限 6000，与包读取入口一致；出现 partial 用相同选段和 `--offset` 续读所需内容。脚本记录实际读取路径、范围、内容摘要、输出字节与耗时，`summary` 给出短统计。这是演练采样，不增加日常接入工具要求。

演练后运行 `check --root <临时目录>`，验证历史/业务/源码及其他改动和原索引保留、没有越权提交或预建空目录、新增 Markdown 本地引用可达和重复接入无差异。早期没有索引快照的演练仅核内容，索引从原请求与实际 Git 状态另核。脚本不能证明入口语义；主 Agent 对照原请求检查实际入口、冲突修正、普通/拆票/子代理/完整调度的触发条件及保存回执。

比较读取量、读取调用、重复读取和原始运行时长，同时报告遗漏、必要澄清与修复。调用数或时间下降但验收变差不能算改进；孤立场景不能证明所有宿主长期速度或 token 收益。允许没有明显提速的结果，按实测决定是否继续调整。必要结论只留在本轮已有运行记录，保留输入与必要产物；无用现场按包操作收尾。


## 新目录与迁移分支

旧 prepare/check 接入场景和保护继续使用，不把只准入口编辑放宽为任意迁移。专项迁移另用显式整体清单，覆盖现行需求物理迁入、glob/生成消费者、独有信息、活动任务、未跟踪附件、intent-to-add 和索引；归档与删除分别判定，保留恢复来源。

布局演练使用候选真实资源的不相邻复制及链接入口，核来源歧义、同名外来源、缺失、越界和固定摘要变化；路径通过不等于 Agent 在正确时机读取。软件与源资料/派生表项目沿同一职责裁剪，无内容不建应用测试、部署、空票或空ADR。

少量对照优先完成验收与反例，然后用同请求、同模型/强度、同夹具的新隔离根对比读取与实际动作。read_seconds不是任务总时长，字节不是Token；宿主usage不可见就注明不可见。真实Codex触发与安装须单独实测，不能用设计阶段路径模拟代替。
