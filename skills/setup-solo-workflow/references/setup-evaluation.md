# 接入场景验证

只在修改接入行为或调查已发生的接入失误时使用。普通项目接入按 SKILL.md 收尾，不运行整套演练。

使用包内 `tests/setup_fixture.py prepare --root <本轮临时目录> --skill <固定版本 SKILL.md>` 建立隔离项目。确需比较旧版与候选时，按真实来源和固定版本定位 improve-workflow 的 `references/behavior-evaluation.md`，复用其基线、同一冻结模板、执行隔离、裁决与成本规则；不假设技能目录相邻。此处只保留接入场景与夹具保护。

原始请求：“为这些项目接入个人工作流，保留项目既有选择和其他修改；仅做工作流与文档接入，交付保存状态，不启动产品实施、提交、推送或生产服务。”

| 场景 | 原始材料 | 验收 |
|---|---|---|
| 已配置老项目 | 既有票源、状态、领域文档、检查配置与角色 | 复用主人及实际技术栈，识别关键风险、已有保障、最小真实接缝和写入隔离；只补事实与缺口，保留有效规则 |
| 规则冲突 | 当前需求与旧角色的规格指针/复位方式不一致 | 关联真实任务规格，保留他人修改与角色责任；冲突有明确适用范围 |
| 未提交资料 | 已修改需求、未跟踪附件、intent-to-add 文件 | 原件逐字保留，新增指针可达，保存状态与未来 worktree 基线据实区分 |
| 重复接入 | 已有完整入口及绑定，栈、风险与保障事实未变 | 复用原文件、协议和有效证据，无新增镜像、测试矩阵或无意义差异；确有新缺口只补缺口 |

语义验收核实际配置与产物：已有检查足够时是否复用，重要规则/严重缺陷/数据权限风险是否仍有稳定回归，mock 的覆盖声明是否止于模拟范围，写入隔离缺口是否阻止依赖它的运行。低风险已有覆盖与不同技术栈的高后果写入分别取代表案例；不以关键词出现、文件存在或保护检查通过代替行为完成。对照旧版已能正确完成且候选无稳定收益时，保留旧版或只采必要补缺；有限样本不证明统计或 Token 收益。

执行者用夹具的 `read` / `inventory` 读取演练文本；read 可选行范围或 `--headings`，默认 2000 字符、`--limit` 上限 6000；出现 partial 用相同选段和 `--offset` 续读所需内容。脚本记录实际读取路径、范围、内容摘要、输出字节与耗时，`summary` 给出短统计。这是演练采样，不增加日常接入工具要求。

演练后运行 `check --root <临时目录>`，验证历史/业务/源码及其他改动和原索引保留、没有越权提交或预建空目录、新增 Markdown 本地引用可达和重复接入无差异；`summary --root <临时目录>` 汇总采样。早期没有索引快照的演练仅核内容，索引从原请求与实际 Git 状态另核。原样未做也可能通过保护检查，check 不是任务成功评分；主 Agent 另核实际入口、冲突修正、普通/拆票/子代理/完整调度的触发条件及保存回执。

必要结论只留在本轮已有运行记录，保留输入与必要产物；无用现场按包操作收尾。


## 新目录与迁移分支

旧 prepare/check 接入场景和保护继续使用，不把只准入口编辑放宽为任意迁移。专项迁移另用显式整体清单，覆盖现行需求物理迁入、glob/生成消费者、独有信息、活动任务、未跟踪附件、intent-to-add 和索引；归档与删除分别判定，保留恢复来源。

布局演练使用候选真实资源的不相邻复制及链接入口，核来源歧义、同名外来源、缺失、越界和固定摘要变化；路径通过不等于 Agent 在正确时机读取。软件与源资料/派生表项目沿同一职责裁剪，无内容不建应用测试、部署、空票或空ADR。

真实宿主触发与安装须单独实测，不能用设计阶段路径模拟代替；通用对照与采样局限按上述行为协议处理。
