# Matt 工程技能的项目配置

在个人 setup 内处理已使用或明确要接入的 Matt 工程技能所需的项目规则。核实目标宿主实际能用的消费者、仓库入口（`AGENTS.md`、`CLAUDE.md`）、现有 tracker、标签和领域资料。仅中央库有安装记录不足以证明项目使用；普通实施或未采用的项目跳过本分支。

1. **票库。** `to-spec`、`to-tickets`、`triage`、`wayfinder` 等使用票库时，先复用已有票源和操作约定；Git 远端只是线索。尚未确定则推荐与现有票据和授权相符的选项，由用户确认。票库正文归 `docs/agents/issue-tracker.md` 或既有主人；按实际消费者记录出票、查票和必要的分诊、依赖或 Wayfinding 操作。切换票库、改旧票、写远端配置各按当次授权。
2. **标签。** 按消费者实际读取的角色确认已有映射；出票技能需要映射时也检查这一项。没有映射则确认采用原名 `needs-triage`、`needs-info`、`ready-for-agent`、`ready-for-human`、`wontfix` 或项目已有名称。映射归 `docs/agents/triage-labels.md` 或既有主人；本地文件记录映射，远端实际标签变更须有对应授权。没有标签消费者时跳过。
3. **领域文档。** 使用现有上下文和实际领域资料。无真实多上下文需求时使用根 `GLOSSARY.md` 和 `docs/adr/`；有多上下文证据时先确认布局。将读取约定放到 `docs/agents/domain.md` 或既有主人；术语和 ADR 按需创建，接入不生成空正文。

在有效项目入口合并 `## Agent skills` 下适用的指针，复用既有正文；规则缺失才补，未批准的选择停在草稿。核对实际消费者能从入口找到需要的配置；再次接入相同输入应无变化。上游模板按需从已核来源读取，作为草稿参考；此分支可在同一次个人 setup 中完成项目配置，无需自动调用仅限用户手动触发的上游 `setup-matt-pocock-skills`。保留上游安装及文件，技能安装和其他项目部署另行处理。
