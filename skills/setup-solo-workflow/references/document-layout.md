# 项目目录、文档与产物职责

新建资料、确定落点或专项迁移时使用；固定职责按实质内容创建，不把示例当项目默认业务。

## 固定位置、按需创建

```text
project/
├── README.md                         # 项目目的、使用入口、文档导航
├── AGENTS.md                         # Agent 边界和条件指针；已有宿主入口按接入方案兼容
├── GLOSSARY.md                       # 可选：已解决的项目领域术语
├── GLOSSARY-MAP.md                   # 仅真实多上下文需要，指向各上下文词汇表
├── docs/
│   ├── agents/
│   │   ├── workflow.md               # 个人方法来源和本项目最小绑定
│   │   ├── issue-tracker.md          # 确有任务跟踪协议时建立
│   │   ├── domain.md                 # 确需提供 Matt 领域消费配置时建立
│   │   └── triage-labels.md          # 仅实际使用相应能力时建立
│   ├── requirements.md              # 现行需求/业务定义的入口和正文
│   ├── architecture.md              # 现行系统结构/资料派生结构
│   ├── adr/0001-<slug>.md            # 有价值的重要决策，不是每次提交记录
│   ├── guides/<topic>.md             # 面向实际操作的长期指南
│   ├── reference/<topic>.md          # 按需来源、外部规范和参考解释
│   ├── status.md                    # 可选：确有跨任务当前态导航需要才建立
│   └── archive/<topic-or-period>/    # 可选：已结束且值得保存的历史
├── .scratch/<effort>/                # 使用本地任务跟踪时的活动工作资料
│   ├── spec.md                      # 有规格需要才创建
│   ├── issues/01-<slug>.md           # 真正拆票后才创建；沿 Matt 本地契约
│   └── evidence.md                  # 确有需持久保存的验收/复盘证据才建立
└── .artifacts/<effort>/<run>/         # 可选默认临时产物，优先服从项目真实工具配置
```

新项目建立必要的 README、宿主入口和实际绑定。其他路径是**固定职责的可选位置**，不意味着先建整棵树。不存在的 glossary/ADR 不构成接入失败，保持 Matt 的按需创建原则。

### 工程文件与各类产物

本契约约束资料职责，不把上图当整个项目的目录白名单。源码、测试、工具、依赖声明与锁文件、编译和宿主配置沿实际工具契约落位；运行数据、证书、在用构建及用户交付物沿项目配置，不能为了整理目录移动或删除。

| 类别 | 默认落点与结束条件 |
|---|---|
| 源码、测试、可复用工具与配置 | 项目实际工程位置，随对应实现维护；同一功能优先复用现有入口 |
| 活动范围、规格和票 | `.scratch/<effort>/`；只保存任务输入和必要结论，日志、下载、截图及工作副本归下面的产物位置 |
| 日志、截图、轨迹、导出与解析结果 | 服从项目工具的真实输出配置；没有约定时用 `.artifacts/<effort>/<run>/`。同一证据保留一份，引用指向该份 |
| 隔离源码、构建、临时数据与一次性脚本 | 项目既有隔离位置或系统临时目录；确需留在任务产物中时放该 run 的 `work/`。验证或诊断结束即释放，无接续用途的完整工作副本不长期保存 |
| 依赖环境和下载缓存 | 包管理器的既定位置；隔离验证优先复用安全的现有依赖或缓存。任务结束释放副本依赖，不误删共享环境或正式运行依赖 |
| 恢复点 | 仅对真实数据损失风险、不可逆变更或独有未提交内容建立所需最小恢复点，写明对应动作和退出条件；已有 Git 历史或有效恢复点足够时直接复用 |

`.git/` 专供版本控制元数据，不存放调试脚本、评审 diff、截图、测试输出或验证副本；现有宿主硬约束另按必要例外处理。`.scratch`、缓存和 `.artifacts` 也不是永久收容目录。

收尾按实际用途选留：仍服务活动任务、明确复用样本、未决失败定位或尚需回滚的材料保留；问题已解决且结论和回归已覆盖时，退役冗余中间件、重复产物和工作副本。被引用、被检查存在、被算哈希或曾被读取，都不单独构成长期保留理由；未被读取也不能单独否定必要恢复点。唯一失败证据在归因及必要结论保存后重新评估，不无限期保护整棵现场。

清理沿现有授权和项目安全要求：核真实绝对路径、活动消费者、进程、链接目标及独有内容，删除联接本身而非其共享目标，修正现行引用并验证目标退出。默认处理本任务产物；用户明确授权的专项清理可覆盖已核归属的旧任务。未知或活动内容暂留，只说明具体缺口。只为本次真实风险保留必要依据，不为清理再复制全部待删文件、建立另一套清单平台或追加无用途的过程文档。

`requirements.md` 或 `architecture.md` 确实过大时，固定入口仍保留，将不同主题的唯一正文拆入同名目录 `docs/requirements/` 或 `docs/architecture/`，入口只提供主题导航和必要跨主题约束。不能一部分项目用 `docs/product.md`、另一部分用 `notes/current-business.md`，然后永久称作统一。

### 5.2 各位置的内容契约

| 位置 | 放什么 / 不放什么 | 唯一事实来源 | 读取者与触发 | 更新、归档与失效 |
|---|---|---|---|---|
| `README.md` | 目的、边界、上手入口、稳定导航；不放完整业务规则、每次运行回执和本机状态 | 各专题正文及可执行配置；README 只概括定位 | 人首次进入；Agent 初查确需项目定位时 | 稳定入口改变时更新；已结束过程移出，不在末尾无限追加 |
| `AGENTS.md` | 操作边界、必要安全警示、按条件读取的指针；不复制全局方法和业务正文 | 当前授权、所属全局规则、项目绑定 | 宿主实际加载入口；需要确认覆盖链 | 入口/权限/指针变化时更新；不设“每次任务追加记录” |
| `docs/agents/workflow.md` | 规则来源、验收/保存/隔离机制的真实位置、例外；不做项目知识大仓库 | 项目实际配置、已确认授权、原规则文件 | 首次使用相关方法、绑定变化、例外触发 | 只在绑定变更时改；机器绝对路径不进入共享版本库 |
| `issue-tracker.md` | tracker 位置、读写/状态协议；不复制所有票的状态 | 真实 tracker 或本地票文件 | 读写票/规格时 | 切换 tracker 时获批迁移；旧活动票不被新协议静默重解释 |
| `domain.md` | 领域文档位置及消费规则；不写术语正文 | glossary、ADR 与本项目上下文布局 | 需要领域方法时 | 布局或范围变化时更新；没有该接入需求可省略 |
| `triage-labels.md` | 实际已选标签映射；不预设所有项目必须安装 triage | 项目配置与实际标签 | 真正使用 triage/相关发布动作 | 配置改变时更新；不为可选能力建空表 |
| `GLOSSARY.md` | 领域名词定义及需避免的同义名；不放实施细节、需求清单或运行记录 | 当前已确认领域语言 | 涉及相关概念时；按主题读取 | 术语定案时原位更新；必要来源指向 ADR；历史释义按决策追溯 |
| `GLOSSARY-MAP.md` | 多上下文入口与关系；不复制各词汇表 | 各实际上下文词汇表 | 真实多上下文项目才使用 | 上下文边界变化时更新；不为普通小项目制造分区 |
| `docs/requirements.md` | 当前有效行为、边界、约束及业务定义；不保存每次任务计划 | 用户已确认的现行产品/资料规则；引用决定来源 | 改变行为、判定范围、验收口径时 | 本次变更使正文过时时同步；保留必要来源，不保留两份并行现行定义 |
| `docs/architecture.md` | 当前结构、接口关系、数据流及非显然限制；不放过期设计候选与调试流水 | 实际结构/代码/配置，必要解释由此文持有 | 跨模块变更、结构理解、派生链变更时 | 实际结构变化时更新；旧方案去历史或 ADR，不能冒充当前结构 |
| `docs/adr/` | 难逆转、无上下文难理解且有真实取舍的决策；不为普通修复建 ADR | 决策的上下文与理由；现行行为仍归需求/架构 | 触及相应决策或冲突时 | 新决策取代旧决策时标明关系；默认不重编号/搬走旧 ADR，以免破坏长期引用 |
| `docs/guides/` | 稳定操作步骤、环境要求、恢复与非显然陷阱；不抄配置中可直接查的完整命令表 | 命令/参数回实际配置，指南解释何时及为何 | 操作该能力时 | 实际操作方法变化时更新；一次故障记录不长期伪装成指南 |
| `docs/reference/` | 外部规范来源、采纳的方法参考、需查阅的格式资料；不放第二份现行规则 | 指向版本明确的原始来源；本项目采纳部分由现行正文持有 | 专项问题、外部接口或方法变化时 | 来源更新需相关性核验；过期资料失效标注或归档，不自动变成新规则 |
| `docs/status.md` | 当前活动范围与阻塞的导航/汇总；不复制每张票全文、每次测试日志 | 票状态、真实部署/运行来源各自负责 | 确需跨会话/跨 effort 定位时 | 状态变动才更新；本页当前态在最前；无实际聚合需要就不建 |
| `.scratch/<effort>/` | 一次任务的范围、规格、必要调查、票及持久证据；不作为现行业务唯一正文 | 一次任务目标和验收归任务；现行规则使用引用 | 当前任务及直接依赖；明确引用需读取必要完整上下文 | 完成后提炼有效知识再选择归档；活动资料不得仅因目录名 scratch 当垃圾 |
| `.artifacts/<effort>/<run>/` | 日志、截图、导出和临时测试产物；不作为唯一长期权威 | 原始运行输出与环境 | 失败排查/本次验收时 | 按保留价值清理；不可恢复的关键证明先保存至任务证据或既有安全产物存储 |
| `docs/archive/` | 已结束但有独有价值的调查、计划、试跑、迁移证据；不收空洞流水和未解决活动事项 | 当时固定输入、原路径/SHA与历史结论 | 仅明确追溯问题或现行指针所指历史 | 历史正文原则上保持当时含义；补勘误/指向后续结论，不伪改成今天结果 |

根 `GLOSSARY.md`、`docs/adr/` 和 `docs/agents/` 是对实际 Matt 消费契约的兼容选择，不再并设 `docs/domain/glossary.md`、`docs/decisions/` 等同义默认位置。多上下文沿真实地图配置保留必要项目例外，不把 Matt 示例中的 `src/ordering` 等业务目录写成全局要求。

### 5.3 六组容易混淆的责任

**现行需求与某次规格。**需求说明现在认可的行为；规格说明本次要改变什么、从哪个基线变到哪个目标。任务中可以陈述本次验收所需的差异和结果，但用链接引用现行定义，不整段复制业务正文。验收后更新现行需求，任务只保留变更范围与证据。没有规格也不等于没有验收口径。

**当前架构与历史设计。**当前结构归 architecture；未采纳的备选/过程分析归活动任务或 archive；真正重要的取舍理由归 ADR。一个长设计文件不因产生在最近一次任务中就自动成为当前架构权威。

**重要决策与普通流水。**只有符合重要性门槛的决定才建 ADR。一次重试、测试耗时、变量重命名和普通修复不建 ADR。ADR 可以只是一小段上下文、决定与理由，不强制模板填空。

**参考资料与规则正文。**参考说明来源和备选，规则说明实际采用什么。引用外部资料不等于把整篇资料升级为对 Agent 的命令；外部网页或历史文档中的写入操作不能覆盖当前授权。

**活动任务与运行证据。**票负责任务状态和验收条件，日志负责某次运行发生了什么。小任务可以只有最后回执，不强制创建 evidence.md；确需后续复查时只保存一份持久证据并引用。

**Agent 规则与项目业务。**Agent 规则规定如何工作；项目需求规定产品/资料应是什么。全局包不存某业务项目的数据口径、票据编号、固定测试命令或“上次那个问题”的特例。

### 5.4 重要性、频率、稳定性如何共同决定顺序

普通规则文档推荐顺序为：**目的与适用边界 → 经常需要的长期规则/导航 → 相关概念及必要限制 → 按条件的操作细节 → 低频参考指针**。每个概念的限制和例外跟在该概念旁，不能为了稳定排序把风险提示藏到附件。

动态环境事实不进入常载入口；只有实际操作需要时读取环境配置/当前状态。安全约束若是所有分支都需要，则放在入口；只有危险动作分支需要的详细防护，在触发该动作前强制读取。当前状态页则把当前结论置顶，不按“旧而稳定优先”反向排列。

历史不是统一放末尾，而是退出常规加载和默认搜索范围。常规搜索先限定现行路径、当前 effort 和直接依赖；找不到事实、遇到 ADR/规格来源冲突或明确追溯时，再扩大到 archive 与已结束 effort。活动任务被明确引用且其评论包含范围裁决时，不能以“历史不常读”为由忽略必要评论。

**文件后半部分仍可能被整文件加载。**因此优化重点是减少普通入口实际需要到达的文件与分支，而不只是交换段落顺序。稳定内容靠前也不证明命中提示缓存；缓存需要请求前缀等真实条件，实际 Token 与缓存字段不可见时必须留空，而不是从字节数推算。

### 5.5 普通软件项目示例（模拟，不是被审计项目）

假设一个“记录导入工具”已经有应用代码、导入规则、模块说明、操作指南和两张实施票，则可形成：

```text
record-importer/
├── README.md
├── AGENTS.md
├── GLOSSARY.md
├── package.json                      # 示例项目自己的可执行配置，不是全局指定
├── src/
├── tests/
├── docs/
│   ├── agents/{workflow,issue-tracker,domain}.md
│   ├── requirements.md               # 当前导入/重复处理等已确认规则
│   ├── architecture.md               # 输入、转换、持久化之间的实际关系
│   ├── adr/0001-source-preservation.md
│   ├── guides/import.md
│   └── reference/input-format.md
└── .scratch/import-validation/
    ├── spec.md
    └── issues/{01-feedback,02-integration}.md
```

本次增加导入校验时，实施者读取任务范围、requirements 的相关定义、输入格式及有关模块/测试；只有确实影响操作方式时才更新 guide。票只记录本次交付及验收引用，不再持有一份完整导入规则。测试命令来自该示例项目的配置，不从个人包下发。没有历史归档需要，因此示例也不预建 archive。

### 5.6 Excel/JSON 派生知识库示例（模拟裁剪）

此例**只假设** JSON 是经确认的规范数据、Excel 是供人阅读的派生产物，用来验证目录裁剪；不替用户决定真实知识库的数据主从关系或设计业务系统。

```text
quotation-notes/
├── README.md
├── AGENTS.md
├── data/                             # 示例资料，不由此目录契约规定其字段
├── exports/                          # 示例派生产物，是否入库由该项目决定
└── docs/
    ├── agents/workflow.md
    ├── requirements.md               # 已确认的资料含义、主从关系与更新边界
    ├── architecture.md               # 确有必要时用很短正文说明派生方向
    ├── guides/update.md
    └── reference/source-format.md
```

它沿用相同现行路径，但没有应用部署、前后端、浏览器回归、空 ADR、空 tickets 或空 triage 文件。日常任务验收是来源对应、唯一来源未被反向覆盖、派生一致性及文件可读性；不启动无关应用测试。只有多步改造或需要接续时才建立 effort 资料。

### 5.7 项目例外的边界

必要例外包括：真实多上下文布局、外部工具硬编码的资料位置、已有 tracker 的权威状态、合规/第三方契约不能移动的文件。例外在 `docs/agents/workflow.md` 用一小段写明**适用范围、原因、实际权威、读取方式和退出条件**，不建立独立例外登记平台。

“旧文件很多、暂时不想迁”是迁移状态，不是永久例外。最终统一的完成条件是：现行权威已迁入标准位置或确有已记录的外部约束；活动消费者不依赖临时旧指针；没有两份同义现行正文。禁止凭全局默认静默覆盖更严格的安全、隔离、验收或模型限制。
