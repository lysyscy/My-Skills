# 本地来源路径的异常恢复

仅在Manager登记缺失本地来源、原路径失效或同名导入分配后缀副本时读取。正常维护回[维护与分发规范](package-operations.md)，CLI入口和参数仍由原版manage-skills持有。

## 先确定问题与归属

核本机实际CLI版本、原技能ID、来源、中央库及部署内容。`source_ref`为空与check未比较本地来源是两类问题；CLI 1.43.0会跳过本地check，官方1.43.1已修复该检查，不能据此推断丢失的路径也会补回。用实际文件比较判断内容，保留当前有效的ID、标签、Preset和部署范围。

先从项目规则、既有登记及已核实作者目录确认应绑定的维护源。可备份元数据会省略local/import的本机路径，恢复或数据库重建后可能缺失；具体个案的历史原因须有证据，不自动归因。不得凭名称相同就选择另一目录作源。

## 保留原登记的同内容补绑定

官方CLI没有专用的本地set-source入口时，先核对应版本的官方安装实现。1.43.0已通过隔离及实际同步验证：安装器实时比较相对路径与文件字节，内容相同则复用原中央路径；登记按该路径更新原技能行和来源路径，关联ID保持。只有确认本机版本仍满足此条件时，才使用以下恢复办法。

1. 记录原登记、已授权部署集合和公开文件指纹；将新版维护源完整保存到本次恢复目录。核源和目标没有并行编辑、独有增量或待处理写入，私密配置保持原位。
2. 在已确认的固定维护源路径临时放入中央库当前的同内容公开文件，经官方`install --local`导入。核返回仍是原ID，并回读来源路径、标签、Preset和部署集合。意外生成新登记或其他身份变化时停止；新增副本仅在明确属于本次操作时按原版Manager能力清理，不删除旧登记。
3. 在finally中恢复保存的新版源并核原指纹；任何失败都先确保新版源可恢复，保留必要证据。源目录出现未预期修改时保护该增量，不覆盖或删除来凑成相同内容。
4. 补绑定成功后按正常update更新新版源，核实际刷新结果、公开文件及原部署范围；不明结果先回读对账。绑定修复在已有同步授权与相同身份/范围内执行；改变维护归属、登记身份或部署范围仍按本次授权裁定。

这是一条经版本核实的恢复方法，不是日常重装流程。不直接改数据库、伪填源信息或强制覆盖未知内容；不为补本地路径创建Git仓库。
