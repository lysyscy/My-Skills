# 候选归因、归属与取舍

读者：执行 improve-workflow 的 Agent。本文件接收主入口取证与扫描得到的候选，拥有原因分析、归属、作用/成本及验证选择；候选发现回主入口，实施与唯一收尾回 implement-solo-spec，包维护回 [package-operations.md](package-operations.md)。

## 解释原机制与候选差异

把观察写成“触发条件与证据 → 原机制缺口或持续成本 → 要改变的行为 → 能检出差异的反馈”。核真实入口、实际执行版本和已有能力，区分规则缺口、入口失联、执行偏离、工具能力与历史迁移问题。对尚未造成错误的保护缺口，说明会漏掉什么、现有替代保护及发生后果；机会有价值不以本次出错为前提。

“执行偏离”是现象分类。结束归因前核指令是否被触达、在该场景是否明确且可操作、相邻规则的优先级与决策责任是否一致、反馈能否及时检出失败。文字已经存在不能证明机制足够；一次真实失败也可能揭示歧义，次数只作佐证。保留“现有机制足够”时，说明可用机制、此次失效原因和恢复反馈；材料不足则保留待判定。

## 找到最小责任范围

| 证据与判断 | 处理与落点 |
|---|---|
| 原规则明确可达，但实际没有执行 | 修真实失效的入口、反馈或约束；偶发失误已被有效反馈检出并纠正时，可保留原机制。发现歧义或冲突则修原规则，避免另加同义提醒 |
| 去掉仓名、业务常量和本机路径后，触发条件与解决机制仍适用于另一种项目 | 可提炼为个人方法，先合并已有同义规则；接入缺口回 setup-solo-workflow，实施/验证/审查缺口回 implement-solo-spec，复盘/选择/包维护缺口回 improve-workflow |
| 依赖具体业务、框架接口、执行器、服务现场或授权才成立 | 回项目现有业务权威、配置、检查、约束或待办；通用入口只留必要条件指针 |
| 一个发现同时含通用方法与项目能力缺口 | 分开动作、主人和反馈，分别核授权；已获准部分继续实施，其余部分保留建议或既有项目待办指针 |

一个项目的证据可以揭示通用机制，须说明可迁移依据，不能用样本数代替因果判断。例如“大场景调试小问题”：最低成本反馈策略归实施方法，某仓执行器的用例拆分能力归该项目；个人方法不保存该仓命令、数据量或固定超时。

## 比较作用、成本与结论

先比较保留原状、恢复已有机制、删减/澄清、补检查或引入能力中实际适用的路径。说明候选替代什么，收益作用在哪些任务，增加多少读取、执行、维护与人工判断负担，以及可能损失的保护。用已有真实轨迹或结果支持判断；无原始数据就作定性比较，不估算 Token、时长或收益比例。

| 结论 | 判据与后续 |
|---|---|
| **建议采用** | 原因、主人和预期改变明确，已有路径不足，作用值得新增成本；列出最小改动及反馈，在已有授权内实施。建议本身不等于已经验证收益 |
| **拒绝** | 已有机制足够、重复建设、作用不抵成本或损失必要保护；说明保留的机制和理由 |
| **待验证** | 候选有价值但原因、有效性或代价仍不确定；给出能区分假设的最小观察和停止条件，而非先加规则再找理由 |

每个保留候选应能回答：依据是什么、机制差异是什么、谁维护、影响与成本如何、用什么真实动作/产物判定有效，以及哪些部分尚未获准或核实。分析到能支持取舍即止；没有动作价值或证据不足时可以结束，不要求每轮都有项目与通用两类改动。

## 选择验证反馈

已知坏链接、过时输入、机械检查或接线等确定性问题，按真实消费者、原缺陷及相关回归验证。观察反馈要能区分问题解决、复发和必要保护退化，文本存在或结构通过只能证明各自范围。

普通规则调整优先读 [behavior-evaluation.md](behavior-evaluation.md) 的轻量分支，在正常授权任务中观察，复用已有记录；没有可反驳的假设或足够材料就保留待验证。需要更可信的因果/成本比较，或普通观察相互矛盾且继续试验有实际决策价值时，才读严格对照分支：先核获准维护、固定旧版问题仍存在、隔离与成本值得，再观察旧版、明确原因和生成候选。无候选、无收益或无结论可保留旧版；实验不创造实施、发布或安装权限。

## 按需能力与长期采用

当前工具不足、接口不熟或反复出现工具性工作时，读取 [capability-selection.md](capability-selection.md) 的唯一选择正文，复用其搜索和隔离小场景证据。这里判断是否值得长期采用；单项目能力仍留项目，共用方法回所属技能。普通实施单独读取该参考不启动整轮复盘。

## 上游适配与完整调用

外部原版保持原渠道独立维护，个人包只维护必要适配和引用，不复制或翻译整份原版形成第二上游。完整调用 retro 或其他原版时，先定位并实际读取该版本，遵守其必要步骤与确认；缺资源或与本次权限冲突就说明缺口，不能裁剪后声称完整执行。

本机资源指纹只提示变化，既不证明兼容，也不代表发现远端未安装更新。适配时只核本次实际消费的输入、产物、动作、副作用、引用和授权，复用未变且未受影响的证据，不逐份融合上游新功能。变化依赖与必要原件按包操作固定和保护；未核契约保持待核，声明加入或指纹一致不代替验证。
