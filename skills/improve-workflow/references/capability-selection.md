# 针对实际缺口选择能力

只有当前工具不足、接口不熟、反复失败或准备大量工具性代码时读取；已有能力足够就结束。本参考不启动整轮复盘。


本节由 improve-workflow 在复盘发现具体能力缺口时读取；普通实施按项目已采用规则寻找适用能力，不以本节为默认前置。调用本节只是选择能力，完整调度与维护生命周期继续由调用者承担。通用工作流只维护选择条件与判断方法；项目维护具体工具、运行入口、适用范围和例外。专用工具技能按其来源维护操作说明，不能因一个项目采用而变成其他项目的默认选型。

1. 写清当前缺口、输入与所需产物，先查现有项目机制、CLI、库、已安装技能、已连接 MCP/插件及平台能力。足够则复用并结束搜索，无需每个普通任务联网。
2. 缺口仍在时按需查官方或可信来源的成熟方案，覆盖 CLI、库、技能、MCP/插件及平台能力中与缺口相关的选项。按个人路由仅消费 find-skills 的发现方法，安装仍由 Skills Manager 承担；完整采用外部技能时先核其动作及授权。find-skills 只承担技能发现；技能无搜索结果不能推出没有成熟工具。信息足以判断时停止，不追新、不默认叠加 CLI/skill/MCP。
3. 核候选实际能力、来源版本、输入产物、权限副作用、兼容性及与现有机制的重叠；比较自行实现与引入的学习、验证、上下文和维护总成本。只需接口事实时引用原始参考；重复触发的独立流程且收益足够时才引入组件。候选不适用时记录原因，按已确认缺口自行实现。
4. 用本任务拥有的隔离小场景证明能解决缺口，再在授权内采用，保留既有有效保障和可靠测试体系。技能安装与分发交 Skills Manager；其他工具、连接及付费按实际入口和当前授权处理。未授权产品改造、账户连接、付费或扩大访问保留待决定；优化技能本身不提供这些权限。

完成选择时留缺口、采用或拒绝依据、真实小场景结果及未决权限，没发现有价值的候选也可结束。示例工具无需真实安装才能演练拒绝与授权分支；夹具结果与真实使用分开报告。
