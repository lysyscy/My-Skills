# 复盘并优化个人工作流

目标是减少用户介入，以及分析、实施、审查和返工的总消耗。My Skills 完整维护仓拥有个人技能、共享资源、管理工具和根目录的 `skill-package.json`；目录发现代替逐项登记。Skills Manager 拥有中央库及各 Agent 的安装、更新与部署。先按[包操作](references/package-operations.md#维护源与安装入口)定位完整维护源，安装技能目录不承担包根。Matt 原版继续独立使用。

## 调用与范围

“复盘并优化个人工作流”、显式调用本技能或用户明确要求优化个人技能，执行完整闭环。仅要求复盘、评估或给建议时只读分析，不因包内自动发布策略开始写入。“按最新个人工作流维护入口接续”沿用原任务范围并保护现有成果。普通产品任务不自动触发复盘优化。

用户指定任务时取其原始会话、差异、验证与现有资料；否则分析当前任务。只读取足以定位问题、规则主人和反馈的材料，后续补缺口或变化，不默认扫描全部技能和会话历史。用户观察是线索，不能代替独立检查。

并行复盘先从未完运行核范围与改动主人，各自在自己的运行中编辑；重叠候选复用已有增量，发布整合后核规则含义和引用的一致性。管理锁只串行保护共享操作，不负责语义协调；忙时先做独立分析，随后有界重试，保留其他运行。耗时归因区分任务总时长、工具等待、测试执行与返工；并行或重复记录不能直接相加为用户等待，缺失计时据实标明。

## Matt更新适配

Matt更新走其原有安装方式；本包不改写或维护原版副本。inspect比较本机实际依赖及资源指纹与上次完成的兼容核验。指纹只是变化信号，不是兼容证明，不能声称已发现远端尚未安装的更新。

检测到更新或尚无兼容基线时，只读发生变化且本次用到的原版，核输入、产物、实际动作及副作用、调用与引用和授权边界；首轮核当前消费契约。适配目标是个人包仍完成原有目标，保留用户选择和质量保障，不逐份融合Matt全部新功能。兼容则沿用；确有缺口时在本轮隔离工作区改个人适配层，必要时更新依赖声明与核验方法。变更授权或减少上游保护才需用户裁定，正常适配自主完成。

这是更新适配模式：聚焦实际变动和消费契约，再进入隔离、验证、发布及同步；不为上游文案更新重做整个产品会话retro。兼容而无个人源变化时运行可无新提交完成，记录本机核验基线。版本在本轮变化时保留新变化待核，不能登记未经检查的版本。行为核验关注项目入口、普通/复杂实施路由及审查责任等受影响关系；未知的新行为按实际版本调查，不预判任意未来版本都兼容。

## 执行

1. **核现场。** 读 [包操作](references/package-operations.md)，用 inspect 的安装事实核入口、未提交改动和未完运行；材料读取与结构校验走其中的 read / structure 入口。优先接续属于本轮的未完工作；其他任务保持原状。开始修改前建立运行、保存源快照和固定执行版本。当前入口尚未安装的宿主，先在隔离工作区读取远端最新入口，再保护并迁入原任务增量。
2. **运行原版 retro。** 从真实安装目录定位 Matt `retro/SKILL.md` 和其 `writing-for-agents` 引用；本轮已保存上游原件时读取保存版本，核实际动作再执行分析步骤。没有原版时说明具体缺项，保留现场，不用自制清单冒称完成 retro。本包消费其分析候选；写入和后续处理按本次授权，不因上游新增动作扩大权限，不改写原版。
3. **提炼与筛选。** 检查原版所有分析类别，主动从实际失败和成本中提炼候选，不限于用户点名项。按[候选归属与外部能力](references/improvement-selection.md)区分规则缺口、执行偏离和项目能力缺口，并完成该引用中的失效归因；混合候选拆出通用方法与项目动作，分别确定主人、授权和证明方式。候选按严重性简述问题、原机制失效原因、落点及不采纳理由；已有机制足够时优先接好或修好它。具体能力缺口需要外部技能或参考时按该引用评估，证据或价值不足则结束，不制造提交。
4. **隔离改进。** 在运行 worktree 修改本轮范围；落后版本用原基线、保存的本轮结果与最新主线比较，迁入有效增量，保留来源不确定性。共用规则在一个主人处修改。项目侧的通用方法只同步必要读取指针；专用约束按当前项目授权更新既有主人或待办，未授权动作保留建议。产品代码、服务与生产资料继续原授权。改变用户既定偏好、上游边界或包维护授权时先准备影响与推荐选择，交用户裁定。
5. **验证与关闭。** 复用 [验证与失败处理、评审及发现关闭](../implement-solo-spec/SKILL.md) 的相关规则，不因此启用产品 effort 调度。结构检查与行为验证分别完成；工具变化在临时 Git 仓和安装夹具中验证。调用子代理前独立读其“模型与推理强度”。需要完整审查时累计范围统一，默认一次；事实确认和已验证修复由主 Agent 关闭，具体未决或未覆盖影响才追加对应审查。
6. **发布与同步。** 同步活说明后核最终输入，在固定工具上验证，按明确文件列表提交，再发布。主线前进时由 Agent 整合和核受影响证据；推送竞争最多三次，必要时保存待发布状态，下一次调用接续。发布后同步本机稳定维护源，由 Skills Manager 更新及部署，再核实际安装结果；部署失败保留待同步运行，继续使用已保存的执行版本。其他电脑下次使用个人方法时自行同步。简述改变、验证、发布和本机同步实值及未决项；不用人工搬运分支回执。

## 自我优化

开始时保存本轮入口、管理工具及既有回归的执行快照。后续管理动作使用快照中的工具，新版只在候选 worktree 和夹具中运行；已知旧回归与新增行为验证共同检查候选。管理工具或验证体系的修改不能只由候选自己宣布通过。需要额外独立行为核验时提供原始任务与材料，不提供预期结论。

本轮源、执行快照、候选版本和安装版本分别报告。新版发布、安装核实后，下一轮才采用它；本轮授权及关闭依据保持不变。必要证据在既有任务主人处留一份；包运行状态承担恢复，不另建长篇台账。清理仅处理本轮拥有且已无接续用途的现场，保留源快照和必要失败证据。
