# 复盘与个人工作流优化

用户要求分析、复盘或审查而未授权本次实施时，只输出结论。已有个人包自动维护授权不能覆盖本次明确只读，也不授权产品项目改造。

创建、修改或分发用户自有技能时，直接读[维护与分发规范](references/package-operations.md)，按唯一维护源和发布分支执行；其余复盘步骤仅在本次确需复盘时适用。

## 找到真实候选

读取用户指定会话或当前任务的真实轨迹、差异、结果和反馈；材料不足时标明可证明范围。按需参考 Matt retro 与 writing-for-agents 的方法，不把没有真实调用说成已运行原版。

使用 [improvement-selection.md](references/improvement-selection.md) 区分规则缺口、入口失联、执行偏离、工具能力和历史迁移问题；明确旧机制为何不够、新机制替代什么、如何从产物/动作验证。没有有价值候选也可以结束，不为完成复盘而增加规则。

获准规则调整的轻量观察，或选择层确认值得严格对照时，读 [behavior-evaluation.md](references/behavior-evaluation.md) 的相应分支；普通产品任务与确定性修复沿原验证路径。

能力缺口读取 [capability-selection.md](references/capability-selection.md)。只影响具体项目的规则留项目，不把业务目录、票号、命令或历史问题写进全局；上游保持独立，不维护复制/翻译副本。

## 分析结束或进入获准维护

只读任务交付采用/拒绝/待验证结论后停止。普通技术方案由 Agent 在已确认偏好内选择；改变用户取舍、维护范围或必要授权才提交裁决。

确实获准维护个人包时，按维护与分发规范定位实际源、安装来源及固定版本。候选按本次授权验证和保存，旧任务继续原规则；候选不能改写自身验收或旧基线来取得通过。

跨技能先按真实入口、所属来源与固定版本定位，不假设安装相邻；实际实施使用同来源 implement-solo-spec/references/execution.md；需要统筹或子 Agent 时按其相应参考执行，不在复盘层增加第二轮审查、验收和收尾。修改指令文档时使用 setup 所属的唯一文档维护规则。

## 维护结果

按风险验证；完整发布授权内依次核源提交及对应成功CI、官方Skills Manager更新与Agent文件、备份远端内容和更新检测，实际步骤回 [package-operations.md](references/package-operations.md)。仅授权候选时止于本地验证和保存；恢复后缺版本基准明确待校准，另一台实体机器不可见就不声称已验。

最终只提供一份必要结果：改进依据、实际修改、验证与未验证部分、源及本机部署状态、未决恢复点。普通项目任务不因读取某份参考而自动进入本技能。

## 更新适配与自我优化

本机资源指纹是变化信号而非兼容证明；不宣称发现远端未安装更新。核本次实际消费的输入、产物、动作、副作用、引用及授权；未变且未受影响的证据复用，不逐份融合 Matt 新功能。用户明确调用完整原版时保留其确认与步骤；找不到原版不声称调用完成。

开始维护时固定源提交与执行规则；涉及自修改或行为试验时保存所需旧版、原回归及实际消费的外部原件，候选在隔离现场验证。新增或变化依赖只对本次实际消费契约核验；未检查的项保持待核，不把声明加入或文件指纹当成兼容证明。已有固定旧运行继续其 entry/runtime 和输入。

并行维护先核范围与主人，按需使用独立 worktree，由唯一负责人串行处理共享 Git 与 Manager 动作。失败先查实际状态再有界重试，保留原件、分支及未决记录；源、候选和实际安装版本分别报告。只清理本轮拥有且无恢复用途的现场。
