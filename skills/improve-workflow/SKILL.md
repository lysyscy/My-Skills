# 复盘与个人工作流优化

这是个人日常复盘入口；按下列四步独立完成，不必每次再读取 retro。普通产品任务或单独查阅本技能参考，不隐式启动全面复盘。用户明确要求完整原版时，按下文的上游分支处理。

用户要求分析、复盘或审查而未授权本次实施时，只交付结论。已有个人包自动维护授权不能覆盖本次明确只读，也不授权产品项目改造。创建、修改或分发自有技能而无复盘需求时，直接读[维护与分发规范](references/package-operations.md)，无需先走复盘步骤。

## 1. 取得可追溯的证据

读取用户指定会话；未指定时用当前任务。以原始请求、实际动作和工具结果、代码/文档差异、验证结果与用户反馈串起预期和实际。对耗时、返工、遗漏或人工纠正，定位发生环节及当时实际使用的规则、入口和版本；成功完成也可暴露持续成本或缺少保护的机会。

复用本次已有材料，只补影响判断的缺口；需要历史轨迹时限定到相关会话。记忆、总结和当事 Agent 的解释可作线索，关键判断回原件核实。材料不足时标明可证明范围；未看到失败不能当作机制有效，也不能臆造长期问题或成本数字。

## 2. 按触发条件扫描改进机会

逐项判断下表的适用条件，命中才调查相应现有机制。七类用于发现候选，不要求每类都有发现或产出一张空检查表；影响结论的未核项要说明。对编码项目，自动检查这一项同时寻找本次错误和已有保护的长期缺口。

| 方向与触发条件 | 核实什么、优先考虑什么 |
|---|---|
| **导航**：定位资料反复绕路，或遗漏隐藏依赖 | 追踪实际入口到权威正文的路径，核名称、条件指针和跨文件关系；优先修原入口或补最短导航，正文留在现有主人处 |
| **自动检查**：复盘涉及编码项目 | 先读项目真实 lint/check/typecheck/test 命令、CI 和本地 hook 配置，核相关检查的覆盖、接线及运行证据。已有检查未接入、跳过或静默失效先作为候选；没有自动运行必要检查的入口本身也是机会，再按后果与成本判断，避免重造检查或默认同时增加 hook 与 CI |
| **审查规范**：审查漏检、规则含糊或标准不一致 | 先区分机械模式与需要判断的要求。固定语法、禁用 API、导入或文件位置等优先交项目现有确定性检查；跨文件一致性等判断留给现有审查规范。需要 Agent 判断的规则再核触发入口、责任及例子，不因此新增固定审查阶段 |
| **AGENTS 负担**：项目或全局常驻指令过重、反复干扰当前任务 | 核哪些内容每次都需要，哪些已有配置、检查、规范或按需参考持有；保留必要边界与导航，把内容归回实际主人。篇幅只作线索，迁移前核真实读取者和触发条件 |
| **工具成本**：调用、读取、输出或等待明显昂贵或重复 | 从真实轨迹核宽泛查询、重复读取、过量输出、可合并调用和工具能力缺口；先用现有工具的筛选、批量和范围控制，比较节省与额外复杂度，保留必要证据和反馈 |
| **无效指令**：指令堆叠、同义重复，或声称改变行为却无对应效果 | 对照真实行为与指令要改变的默认行为，区分无作用、失联和含糊；优先删重或修原规则。未观察到违反不足以证明指令无用，影响保护边界或证据不足时留待验证 |
| **信息访问**：关键事实、日志或外部状态不可得，导致猜测或人工搬运 | 核已有日志、查询接口及访问范围，优先复用可追溯的只读信息源；说明新增访问能解决什么、权限及维护代价。账户连接、扩大访问或产品改造仍按当次授权 |

涉及指令结构、迁移或无效性判断时，定位实际安装的 writing-for-agents，按其指针、层级与行为作用方法核对；原文和消费者共同决定取舍。

发现文档职责混杂、阅读失败或重复维护时，读同来源 setup-solo-workflow/references/documentation.md，用成熟方法的适用部分核读者任务、权威、现状/目标/历史及独立包消费者。文件名或章节不齐不是缺陷；比较保留现状、修入口、拆分或迁移，说明替代的旧正文、维护成本与实际消费反馈。不为标准名称、目录外观或模板覆盖率扩展工作，也不建立另一套文档治理流程。

## 3. 归因并选择最小有效改进

对有依据的候选读取 [improvement-selection.md](references/improvement-selection.md)，核原机制为何不足、原因归属、作用与成本、采用/拒绝/待验证及可反驳的反馈。项目与通用方法分别找主人；一次失误、工具缺口或历史版本问题不自动升级为全局规则。

有实际能力缺口时读 [capability-selection.md](references/capability-selection.md)；需要规则行为观察或因果对照时，按选择参考进入 [behavior-evaluation.md](references/behavior-evaluation.md) 的相应分支。检查足够或没有值得采纳的候选时即可结束。

## 4. 按影响交付结论

优先呈现后果严重、反复发生或影响面广且证据充分的候选，再说明预期作用、成本与不确定性。每项沿选择参考交代证据、原因、主人、建议和验证反馈；相同原因合并，区分建议采纳、已经实施与已验证效果。没有有价值候选时据实说明范围和结论。

只读任务到此停止；普通技术取舍由 Agent 在已确认偏好内选择，改变用户取舍、维护范围或必要授权才交用户裁定。最终保留一份必要结果，维护任务的实际修改、验证和发布状态并入同一回执。

## 按需维护与上游适配

获准维护自有技能时，按 [package-operations.md](references/package-operations.md) 选择唯一维护源、固定执行基线并完成适用的发布核验；候选不能改写自身验收或旧基线来取得通过。跨技能按真实入口、所属来源与固定版本定位，不假设安装相邻。实施与唯一收尾回同来源 implement-solo-spec/references/execution.md；修改指令文档沿 setup 所属文档维护规则，不在复盘层另加一轮审查、验收或发布流程。

外部能力更新、适配或完整调用原版时，读 [improvement-selection.md 的上游分支](references/improvement-selection.md#上游适配与完整调用)。日常复盘消费本技能的方法；原版继续由原渠道独立维护。
